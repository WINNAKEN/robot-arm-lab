## Composition and ownership

New `robot_phone` component composes actual Supervisor and BenchRun through one exact CanPort. Only the serialized control owner may create core sessions, call requests, poll, mint/consume handoff, or touch the port. Boot is terminal before Run starts. No second port or duplicated configuration cache. C's per-setting freshness and diagnostic/stop timing guards remain authoritative.

HTTP task may only receive/validate bounded wire input and send envelopes to the owner. It cannot call a core's open_session/request/status directly: those APIs may inspect deadlines or physical state. The owner publishes copied bounded status/results for HTTP. SDK queue/locking details must prevent data races; never hold a network/mutex wait across a CAN call. Control task polls every1ms candidate (FreeRTOS1000Hz); actual scheduler/API/ISR bounds remain hardware NOT_RUN. HTTP receive/send can block only its own lower-priority task with finite timeouts.

Owner phases are Boot, RunChecking, Run, Stopping, Terminal; monotonically increasing phase generation fences old queued input. No request replay/automatic Acquire/Arm/Ticket/Move across handoff or reconnect. Only explicit authenticated Handoff requests mint/consume actual BootEvidence and preserve its principal/port/deadlines. Two interactive session slots maximum; initial implementation may retain slots for a boot lifetime, clearly reporting SessionFull until explicit reboot. Stateless status reads need not allocate slots. Any slot reclamation instead requires a reviewed expiry/owner-stop/generation contract, never silent reuse.

## Bounded wire contract and trust

Choose a small versioned ASCII POST body rather than a permissive JSON-to-core cast. Exactly eleven pipe-delimited fields: `v1|boot|phase|seq|request|op|lease|ticket|axis|direction|unloaded`. Maximum256 bytes, ASCII only, no escapes/extra fields/signs/whitespace/NUL/trailing data. Decimal unsigned fields check overflow before conversion; boolean exactly0/1; axis0/1/2 and direction0/1, operation allowlist. Wire IDs are decimal strings in JSON status to preserve uint64 beyond JavaScript precision. Tests use handwritten request bytes and inspect actual routed core results.

Server session identity and authenticated principal are not accepted from body fields. HTTP headers carry a server-issued random session credential after pairing; body boot/phase must exactly match copied current owner values. Pairing credential is freshly generated at each prepared ESP32 boot from ESP hardware RNG, never a checked-in fixed token. Session credentials are also random and bound to one internal slot/principal; invalid/duplicate/expired credentials cannot impersonate another slot. Constant-length comparisons avoid partial/prefix matches. Credential, payload and raw CAN are never placed in GET URLs or status logs. Serial onboarding prints credentials deliberately once for the operator; routine logs and API status do not expose them.

Prepared target is local SoftAP only: WPA2 password and pairing credential supplied through serial onboarding on the actual board, no Internet/cloud/OTA. Exact per-listener Host policy: ordinary port80 accepts only `192.168.4.1` (browser's default-port Host); Stop port8081 accepts only `192.168.4.1:8081`. Cross-listener Host, arbitrary suffix/port, missing or duplicate Host is rejected. Both listeners accept only Origin `http://192.168.4.1` for state changes and Stop preflight; no CORS wildcard or missing/null Origin exception. Pairing route also requires pairing credential and correct Origin. Same-origin page holds session credential only in memory; reconnect/reload does not restore motion authority or resend a request. No claim of TLS or protection from an already-authorized credential holder. Host tests inject deterministic credentials through an explicit fixture dependency; no fixture secret reaches prepared target.

Routes on port80: GET `/` serves the embedded page; authenticated GET `/api/status` returns copied owner status; POST `/api/session` pairs/opens a slot; POST `/api/command` accepts only the strict grammar and session credential but excludes Stop. An independent HTTP instance on port8081 accepts POST `/api/stop` only for the same wire grammar with Stop opcode, plus bounded OPTIONS. Distinct TCP and HTTP control-UDP ports and server tasks prevent an ordinary fragmented receive or result wait from blocking Stop ingress. Stop server has exact `Access-Control-Allow-Origin: http://192.168.4.1`, allowed POST/OPTIONS and explicit credential/content-type header list, never wildcard or reflected arbitrary Origin. Other routes/methods and normal operations on Stop port fail. Both instances share the copied-message owner bridge, never live core objects. Browser uses explicit `http://192.168.4.1:8081/api/stop` for Stop; it is separate software-stop ingress, not a physical emergency-stop guarantee.

Pinned SDK public header getters return only the first match and cannot prove duplicate rejection. Each actual server therefore installs the supported `open_fn` plus `httpd_sess_set_recv_override` and per-socket transport context. A portable raw-header guard accumulates at most1024 bytes through CRLFCRLF over arbitrary receive fragments, enforcing request-line/header syntax and case-insensitive uniqueness of Host, Origin, authorization/session credential, Content-Length and Content-Type. Reject obs-fold, conflicting framing/Transfer-Encoding, NUL, malformed CRLF and oversized input. The recv override validates the complete raw header before returning the fragment containing its terminating bytes to the SDK parser. Invalid input returns a socket error/close before URI dispatch; no private SDK struct/header access. Already-delivered partial header bytes cannot dispatch a request without the terminating fragment. Subsequent body reads do not enter the header recorder. Mandatory one request per connection, `Connection: close` and actual session close prevent pipelined data from reusing the guard. New connection gets a new guard/deadline. Portable tests feed the exact same guard fragmented duplicate-header cases; target wrapper must call that guard, not rely solely on ordinary SDK getters.

Content type/length, fragmented body completion and malformed body fail before admission. Exact limits: body256, raw headers1024, ordinary external client sockets2 and Stop external client socket1 (HTTP max_open_sockets5/4 including SDK internal3); LWIP socket allocation16; one normal owner job and one Stop job; owner result wait50ms, no retry; accepted normal enqueue age<50ms at consume; authenticated ordinary commands at most10/s per session with burst4 (permits explicit Arm/Ticket/Move plus a lease renewal), Stop independent of that bucket. Status polling is separately bounded5/s and never renews authority. Socket receive/send timeout100ms, total per-request header/body deadline250ms checked around calls; any timeout closes rather than restarting the total deadline. A network stall or malicious use of the Stop listener can still delay another network Stop; no hostile network availability guarantee is claimed. Separate Stop ingress specifically prevents ordinary work and its response wait from blocking Stop. Never accept user-controlled profile approval/calibration/rawCAN/unlimited pulses/speed/torque settings.

One bounded normal job slot and one independent Stop slot, with finite handler wait for correlated response. Full normal slot returnsBusy; no FIFO of moves, no replace/retry of an accepted move. Stop is serviced before normal work; on Stop acceptance invalidate pending ordinary job and never extend the first stop time. Envelopes include server enqueue time and generation. Owner rejects stale normal jobs before touching core; delay allowance is explicit and less than core observation/lease limits. Stop scheduling delay must also fail closed and cannot manufacture a later deadline. Software stop timing is measured from core's actual owner acceptance, not the phone tap or HTTP receive; queue and network latency are reported separately, never presented as a physical emergency-stop bound.

For the portable component, all adapter/session/queue state has one serialized owner. The SDK wrapper uses bounded FreeRTOS command/result queues, copies envelopes, and publishes snapshots without concurrently reading live core objects. At most one pending HTTP result per handler; late results cannot satisfy a later request (unique job generation), timeout does not auto-retry. Invalid credentials do not consume core sequence or authority. Exact caps/rates are constants with tests; Stop must remain admissible to a valid observer under ordinary-command saturation.
