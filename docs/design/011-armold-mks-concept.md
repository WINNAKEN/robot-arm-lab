# MP3 — Armold 타입 MKS 6축 자체 개념 모델

2026-10-23 사용자: 구매 보류, Armold 타입으로 MKS 모터에 맞는 6축 개념 모델을 SolidCraft로 만들고 표시. 감속기는 기존 공개 설계 참고.

구현 상태: **CONCEPT_MODEL_READY_WITH_ASSUMPTIONS**. L2R1 PASS6/0 후 자체69B-rep/7링크/6revolute native 및 STEP/3MF/3방향 렌더를 생성했고 실제 SolidCraft GUI에 열어 두었다. L4R1의 검증 필드/비작동 입력 두 지적은 수정 후 R2 PASS4/0으로 폐쇄했다. 최종 가정 치수는 `models/armold-mks-concept-v1/parameters.json`, 동결 목록은 `frozen-manifest.json`, 처분은 `.dev/armold-concept-evidence/disposition.md`다.

실제 배치 조정: 원통 하우징 J1/J3 90/J2 104/손목78mm, J1높이96/어깨상승78/상완165/전완140mm, J4→J5 78/J5→J6 140mm. 손목140mm는 MKS 모터/후면 스택의 정적 관통을 수정한 값이다. 기본모터 길이40mm는 여전히 가정이다. 소프트웨어 조인트 영점은 표시 자세[15,-50,70,15,25,-10]도이며 물리적 영점과 범위는 미확정이다. 별도 공개감속 원리도40솔리드는 빈 디스크·핀·입출력 역할의 설명용이며 작동 치형/검증 감속기가 아니다.

## 범위와 기준

- Armold의 관절별 소형 모터/감속기 모듈·직렬 6축 배치를 시각 참고한 **자체 개념 설계**다. Armold 유료 형상이나 Faze4 전체 암을 가져와 새 모델이라고 부르지 않는다. 기존 Faze4/MP1/펌웨어/받은 원본은 보존한다.
- 현재 확정된 것은 MKS SERVO42D CAN MT 2세트 주문이다. 실제 모터 길이·후면 보드/방열판·축·커넥터 치수는 미확인. NEMA17 프레임42.3mm, 몸체40mm, 후면46×46×18mm 및 추가 커넥터 공간은 **교체 가능한 설계 가정**으로 저장한다. 가정값에 맞춘 배치이지 주문품 장착 적합 판정이 아니다. 6개 모터 표시는 향후 구성이며 6개 주문 상태가 아니다.
- 베이스→J1(Z)→J2(Y)→J3(Y)→J4(X)→J5(Y)→J6(X)→공구 플랜지. 이 축들은 각 parent의 영점 프레임 기준이며 실제 world축은 상위 회전을 합성한다. 어깨/팔꿈치/손목 중심과 축·링크 길이·자세를 매개변수/metadata로 보존한다.
- 초기 시각 배치안: 베이스140×140×12, 어깨높이115, 상완165/전완140, 손목오프셋62/55mm. 큰감속기 외형80mm·손목68mm는 개념값이다. 관절 자세는 약[0,-25,55,15,30,-10]도. 모델을 보고 부품이 과도하게 겹치면 배치값을 조정하고 변경값을 기록한다. 직선 링크는 튜브/슬림 구조, 관절은 원통 모듈로 Armold 타입의 방향을 나타낸다.
- 감속 참고: 확보된 Faze4 공개 `docs/B_Design_decisions.rst`, `cyclo_disk_STEP_files.zip` 및 제조STL의 편심 입력·사이클로이드 디스크·핀링/출력부 구성을 참고한다. 원본의27:1/15:1/11:1은 참고 모델 값으로 기록하고 새 로봇의 검증된 감속비·정격으로 쓰지 않는다. v1은 하우징/입출력/베어링 위치를 단순화한 공간 모델이며 제작용 치형·공차·맞물림을 확정하지 않는다. 실제 LICENSE CERN-OHL-Sv2와 README MIT 배지 상충을 명시한다. 원본 설계 코드/매크로는 실행하지 않는다.
- 네이티브는 Base+Link1..Link6의 7개 링크로 구성하고, 각 관절의 모터/하우징은 parent 링크에, 출력 플랜지는 child 링크에 둔다. 기존 CLI의 `joint.as_built`가 제공하는 revolute를 사용해 여섯 관절을 만들고 base를 고정할 수 있으면 실제6DOF/연결/재계산 상태를 확인한다. 이 조립 시험은 설계 기구학 확인이며 운동 범위/충돌/토크 검증이 아니다. API/solver가 지원하지 않으면 제한을 명시한 정적 모델+6축 metadata로 전달하며, 동작 가능하다고 쓰지 않는다. 지원 확인은 최대2회로 한정한다.
