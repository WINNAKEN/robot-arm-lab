# MKS CAN 2축 벤치 시험 준비·구매·시험 계획서

작성일: 2026-10-22 · 프로젝트: robot-arm-lab · 기획 #2
상태: **계획 초안 / 실행 전 / 사용자 검토 대기**

후속 상세: 선택한 ESP32 CAN-U 기준 배선·명령·수령 순서는 [배선·CAN 명령 실행 가이드](003-wiring-and-can-command-guide.md)를 따른다. 이 문서의 초기 PC 진단 구매안과 구분한다. 보호장치·퓨즈·실물 정격·펌웨어 구현은 여전히 미확정 또는 미수행이다.

## 1. 이번에 하려는 일

주문한 **SERVO42D CAN MT 모터·드라이버 2세트**를 선택한 **Waveshare ESP32-S3-RS485-CAN-U**의 CAN 버스에 연결하여,
각 모터의 위치 제어와 읽기, 두 노드 구분, 두 축 동시 운전, 정지 및 통신 단절 대응을 확인한다.
처음에는 링크나 감속기를 달지 않고 모터를 고정한 탁상 시험으로 시작한다.
여기서 ‘2축’은 독립된 모터 두 개다. 2관절 로봇의 끝단 좌표 제어까지 포함하지 않는다.

이번 산출물은 준비물·구매 조건·시험 순서를 정한 계획서다.
프로그램 설치, 제어 코드 구현, 펌웨어 변경, 배선, 전원 인가, 구매는 아직 실행하지 않았다.
모터 시험 성공도 완성 6축의 토크·정밀도·가반하중을 검증한 결과로 해석하지 않는다.

## 2. 현재 확인된 것과 남은 확인

| 항목 | 현재 상태 | 후속 확인 |
|---|---|---|
| 모터·드라이버 | 사용자 확인: 실제 주문 옵션은 **CAN MT**, 2세트 주문 완료 | 수령 시 라벨·CAN 단자·실제 수량 확인 |
| 상품 링크 | [주문 상품 페이지](https://ko.aliexpress.com/item/1005010202913740.html) 제공됨 | 자동 열람 불가. 선택 옵션·동봉품·상품 세부 사양 미열람 |
| 상품 화면 | 첨부 화면의 선택 옵션은 RS485 MT | 실제 주문은 CAN MT라는 사용자 답변을 주문 정보로 채택 |
| 모터 정격 | NEMA17 계열을 전제로 계획 | 정확한 모델, 상전류, 길이, 스텝각, 장착 치수 기록 |

**주문 모터와 드라이버는 추가 구매 목록에서 제외한다.** 화면만으로 RS485 주문으로 재분류하지 않는다.
CAN MT라는 옵션명만으로 펌웨어 V1.0.9나 케이블 포함을 확정하지 않는다.

## 3. 초기 PC 진단 구성 참고

아래는 초기 계획의 PC 진단 경로다. 현재 주 제어기는 ESP32 CAN-U이며 USB-CAN 구매가 필수는 아니다. 도착 전 준비와 ESP32 기준 기능 구성은 [도착 전 준비 계획](002-before-arrival-preparation-plan.md)을 따른다.

```text
Windows PC ─ USB 데이터 케이블 ─ USB-CAN 어댑터
                                     │
                       CAN H / CAN L / 신호 기준 GND
                                     │
                                 드라이버 1 ─ 드라이버 2
                                   ID 1         ID 2

24V DC 전원 ─ DC 차단 장치 ─ 퓨즈·분배 ─ 각 드라이버 전원
                                              │
                                           각 모터
```

그림은 연결 관계다. 단자 번호·커넥터 핀맵·접지 상세 배선도는 아니다.
CAN은 한 줄의 버스로 구성하고 긴 별형 분기를 만들지 않는다.
전원은 두 드라이버에 분배하며, USB 포트로 모터를 급전하지 않는다.

별도 PC 진단이 필요한 경우의 참고 경로는 **MKS CANable 계열 + Windows Cangaroo**다.
제공 공식 매뉴얼 Part 13에 이 조합이 예시로 있다.
[CANable 공식 안내](https://www.canable.io/getting-started.html)도 Windows Cangaroo의
candlelight/slcan 지원을 설명한다. 실제 구매 모델·탑재 펌웨어·Windows 드라이버와
선택한 Cangaroo 배포본의 조합은 판매 사양으로 별도 확인한다.

‘USB-CAN’이라는 이름만 보고 구매하지 않는다. USB-RS485, USB-TTL은 이 구성의 대체품이 아니다.
후속 자동 기록에 Python을 쓰려면 해당 어댑터의 인터페이스 지원을 먼저 검토한다.
이번 계획에는 자동화 코드 제작이나 펌웨어 교체를 포함하지 않는다.

수량은 두 모터를 같은 책상에서 시험하는 최소 구성 기준이다.
보유품·동봉품이 있으면 제외한다. 아래 규격은 선정 조건이며 특정 판매품의 호환 보증이 아니다.
최종 구매 전에는 모터 정격, 어댑터 펌웨어, 단자 규격과 각 부품 정격을 대조한다.
현재 판매가·재고·배송비를 확인한 견적서는 아니다.

전원 선택에서 **모터 상전류 두 개의 합을 그대로 24V 전원 입력전류로 계산하지 않는다.**
드라이버의 전류 제어 방식과 운전 조건 때문에 서로 다른 값이다.
우선 한 대의 저속·무부하에서 전원 전압과 입력전류를 관찰한 뒤 두 대 운전으로 확대한다.
전원 제한에 걸려 보드가 재시작하면 합격이 아니라 전원·설정 재검토 대상으로 기록한다.

첫 구성은 AC 단자가 노출되는 오픈프레임 SMPS보다 외함이 있는 전원 또는 실험용 전원을 우선한다.
이미 보유한 SMPS를 쓴다면 AC 인입·접지·퓨즈·외함 작업은 해당 작업이 가능한 담당자가 별도로 구성한다.
정지 버튼 복귀만으로 모터가 다시 움직이지 않도록 재시작 절차를 시험한다.
이는 벤치 급전 차단 장치 계획이며 안전 인증된 로봇 정지 기능의 검증을 뜻하지 않는다.

## 5. 배선·설정에서 먼저 정해야 할 사항

### 5.1 종단 구성은 단일 모터와 2축 버스를 구분

**현재 Wave CAN-U 구성 확정안:** 1축은 Wave ON/축1 ON, 2축은 Wave ON/축1 OFF/축2 ON. 물리적 양 끝의 내장120Ω을 사용하고 전체 무전원 H–L 약60Ω을 확인한다. 제조사 회로·MKS 예외 비교 근거는 최신 가이드 §2. 아래는 초기 PC 어댑터 선택 때 남겼던 일반 검토 조건이며 Wave 단자표를 대신하지 않는다.

받은 시작 안내문은 버스 양 끝 120Ω 두 개를 준비하라고 안내한다.
반면 공식 V1.0.9 매뉴얼 §2.3은 단일 모터 예시에 종단 점퍼를 연결하지 말라고 적는다.
따라서 ‘상황과 무관하게 두 개 추가’라는 규칙으로 단순화하지 않는다.

- **단일 모터 단계:** 공식 단일 연결 예시와 선택 어댑터 설명서를 대조하여 종단 ON/OFF를 기록한다.
  어댑터 내장 종단을 알 수 없거나 두 문서의 요구가 충돌하면 전원 인가 전 해결한다.
- **2축 단계:** PC 어댑터 → ID1 → ID2의 물리적 양 끝에만 각각 120Ω이 되도록 구성한다.
  중간 노드의 내장 종단은 해제한다. 전원을 모두 끈 상태에서 의도한 종단 두 개가 병렬이면
  H-L 저항 약 60Ω을 기대한다. 보드 회로 영향이나 문서 차이로 맞지 않으면 원인 확인 후 진행한다.
- 신호 기준 GND는 공식 도면과 어댑터 절연 구성을 따른다. 절연형 어댑터의 CAN 측 GND와
  USB/섀시 GND를 임의로 연결하여 절연을 우회하지 않는다.
- 케이블 변경·종단 점퍼 변경·모터선 변경은 전원 차단 후 수행한다.

### 5.2 처음 사용할 설정 후보

| 항목 | 후보 | 확정 조건 |
|---|---|---|
| 통신 | Classic CAN, 표준 프레임, 500 kbit/s | 어댑터와 두 보드 동일 설정 |
| 노드 ID | 1, 2 | 보드 한 대씩 연결해 설정하고 라벨 부착. 둘 다 기본 ID1인 채 접속하지 않음 |
| 운전 모드 | SR_vFOC / CAN 버스 FOC 모드 | 실제 펌웨어 메뉴·매뉴얼 대조. 읽기 응답만 온다고 동작 모드 적합으로 판정하지 않음 |
| 전류 | 모터 정격 이하의 낮은 값에서 시작 | 정격과 보정 절차 확인 후 결정. 42D 최대 설정 3A를 초기값으로 사용하지 않음 |
| 속도·변위 | 초기 목표 5~10rpm, ±10~30° 이내 | 실제 명령의 단위·가속도 의미와 최소 유효값 확인. 보정 동작은 별도 매뉴얼 절차 |
| 전원 투입 시 동작 | 자동 구동·자동 원점복귀 비활성 | 재전원 시험에서 실제 정지 상태 확인 |
| 응답 | 노드별 응답 활성 | ID·명령·상태·위치·에러를 기록할 수 있어야 함 |
| 통신 단절 보호 | 초기 후보 1,000ms, 확인/유지 명령 주기 후보 100ms | 버전별 지원·범위·지속성 확인. 수동 GUI만으로 주기 유지 불가하면 이 시험은 보류 |

위 속도·각도·주기·시간은 **본 시험의 제안값**이며 제조사 성능 보증값이 아니다.
매뉴얼 §5.2.15의 heartbeat는 ‘어떤 호스트 명령도 일정 시간 받지 않으면 정지’하는 방식이며 기본값 0은 비활성이다.
시험 중 GUI의 자동 반복 송신이 계속되면 통신 단절 시험 조건이 성립하지 않으므로 송신원을 모두 확인한다.
설정이 재부팅 뒤 유지되는지도 별도 확인한다.

## 6. 단계별 시험 순서와 종료 조건

앞 단계가 미확인/실패면 다음 단계로 확대하지 않는다.
각 단계는 기록 후 진행하며, 실패 시 그 단계의 원인을 확인한다.
정지·통신 단절 시험도 낮은 속도·무부하·고정된 모터에서 수행한다.

| 단계 | 할 일 | 통과 조건 / 남길 증거 |
|---|---|---|
| T0 수령·정격 확인 | CAN MT 2세트, 모델·버전·모터 정격·단자·동봉품 기록. 구매 목록 확정 | 두 보드 사진·버전·정격표, 전원/어댑터/배선 선정 근거 확보 |
| T1 무전원 점검 | 브래킷 고정, 모터 상 배선, DC 극성, 퓨즈, 단자, 첫 단계 종단 상태 확인 | 회로 연결표와 도통/단락 점검 기록. 전원 차단 장치의 동작 확인 |
| T2 보드별 첫 기동·보정 | 한 대씩 무부하 보정. 두 번째는 분리. 전류 제한과 자동 동작 OFF 확인 | 보정 완료, 오류 없음, 설정 기록. 이상 발열·진동·전원 제한 시 중단 |
| T3 단축 CAN 읽기 | 한 대의 ID·버전·상태·위치 읽기, 이어 다른 대를 분리 상태로 ID2 설정 | 각 보드 100회 조회에서 응답을 해당 ID·명령으로 식별. 누락·잘못된 프레임·응답 오류를 집계 |
| T4 단축 저속 운전·정지 | 각각 작은 상대 이동 → 반대 방향 복귀. 처음에는 한 동작마다 관찰. 정지 명령과 DC 차단을 각각 시험 | 방향·이동량이 의도와 맞음. 상태/엔코더/영상 기록. 정지 후 자동 재구동 없음 |
| T5 두 노드 연결·개별 운전 | 전원 OFF 후 2축 버스 구성·종단 재점검. ID1/ID2 조회. 한 대만 움직이는 명령을 번갈아 수행 | 각 ID 100회 조회. 지정 축만 명령 수행, 타 축의 의도치 않은 동작 없음. 전압 강하·재부팅 없음 |
| T6 두 축 동시 운전 | 순차 명령 기준선 확인 후, 지원 시 동기 플래그로 각 축 명령 준비 → 공통 시작. 서로 다른 작은 변위로 20회 시험 | 준비 중 대기와 시작 후 두 축 동작을 관찰. 두 축 모두 도착·상태 확인. 시작 시차는 측정 장비가 있을 때만 보고 |
| T7 스위치 원점복귀 | 센서 전기 레벨을 먼저 수동 검출. 트리거 기구 설치 후 한 축씩 저속 원점복귀 10회 | 잘못된 방향/스위치 미검출 때 즉시 중단. 매회 검출·정지·오프셋 기록. 단순 무한회전 축의 ‘홈’을 로봇 관절 범위로 해석하지 않음 |
| T8 통신 단절·복구 | heartbeat 설정 후 모든 송신 중단 또는 어댑터 분리. 두 축 저속 시험. 소프트웨어 정지와 전원 차단도 구분 기록 | 양쪽 모터의 실제 정지, 실제 경과시간, 단절 후 상태와 복구 절차 기록. 재접속·전원 복귀만으로 재동작하지 않음 |
| T9 반복·온도 관찰 | 정해진 저속 왕복 패턴 20회, 최소 10분 관찰. 시작·중간·종료 전압/전류/온도 기록 | 미응답·보호 오류·재부팅·비정상 동작 없음. 제조사 허용치 내 운전. 허용 온도 미확인 시 장시간 시험 보류 |

T3/T5의 100회와 T6/T7/T9의 반복 횟수는 이번 계획의 기본 표본 수다.
그 범위에서 정상이라는 결과이며 장기 신뢰성 보증은 아니다.
위치 도착 판정에는 펌웨어 임계값, 내장 엔코더 값과 외부 관찰을 함께 남긴다.
정밀도나 반복 오차의 합격 각도는 측정 장비와 용도 선정 후 확정하며 임의로 ±0.1° 같은 수치를 약속하지 않는다.

### 6.1 동시 시작과 동시 도착을 구분

공식 매뉴얼 Part 12의 동기 플래그 기능은 명령을 보관하고 공통 실행 명령에서 시작하는 방식이다.
이것만으로 두 축의 도착 시간이 같거나 로봇 궤적 보간이 된다고 볼 수 없다.
V1.0.9 문서의 관련 명령은 0x4A/0x4B다. 사용 전 실제 탑재 펌웨어 지원을 확인한다.
브로드캐스트 시작에는 응답이 없으므로, 시작 명령 송신 로그만으로 두 축 실행을 통과시키지 않는다.
각 축의 위치·동작 상태와 영상으로 확인한다.

보유 계측기로 두 축 시작을 같은 시간축에서 측정할 수 없다면 결과는
‘동시 운전 관찰, 시작 시차 미측정’으로 남긴다. ms급 동기 성능을 주장하지 않는다.
제3자 Arctos 문서의 브로드캐스트 관련 설명보다 공식 매뉴얼과 실제 버전 확인을 우선한다.

### 6.2 정지 시험의 판정 방법

정지 명령 수신, 실제 회전 정지, 전원 차단은 서로 다른 사건이다.
T4에서 정지 명령 후 회전이 멈추는지부터 확인한 다음 두 축으로 확대한다.
T8의 정지 시간은 마지막 수신/송신 기준과 실제 움직임을 관찰한 시각을 구분해 기록한다.
heartbeat 1초를 설정했다고 정확히 1초 안에 기계가 완전 정지한다고 미리 판정하지 않는다.
허용 정지 시간은 실제 속도·관성·계측 해상도를 정한 뒤 실행 전 확정한다.
허용 시간을 정하지 못한 결과는 측정 기록으로만 남기고 보호 성능 합격으로 분류하지 않는다.

전원 차단 시 모터의 유지 토크가 사라지고 잔류 회전이 가능하다.
이번에는 중력 하중과 긴 링크를 장착하지 않는다. 중력 관절 시험은 기계적 지지 설계 후 별도 계획으로 다룬다.

## 8. 역할과 착수 전 확정 목록

사용자는 보유 장비·수령품 사양을 확인하고 부품 구매·현장 시험 여부를 결정한다.
문서/소프트웨어 담당은 연결표·명령 단위·검사 기록 양식을 준비하고,
전원·배선 담당은 DC 차단 정격·퓨즈·커넥터·센서 입력을 확인한다.
동일인이 맡더라도 확인 항목은 분리하여 기록한다.

실행 전에 남은 항목:

1. 실제 모터 정격 및 보드 버전, 케이블/단자 동봉 여부.
2. 전원·어댑터·공구 보유 현황과 B01/B03/B08 제품 선정.
3. 단일 및 2축 종단 연결표, 센서 핀맵과 작동 레벨.
4. heartbeat 유지 수단, 중단 조건, 재시작 절차.
5. 시험별 온도·정지시간·위치 오차의 필요한 허용 기준과 계측 가능 범위.
6. 이 계획에 대한 검토 및 실제 시험 착수 지시. 코드가 필요하면 별도 구현 계획과 검수를 수행.

이번 문서는 계획 작성자의 자료 대조를 거쳤으며 **독립 검수는 아직 수행하지 않았다.**
구매나 실험의 실행 승인으로 취급하지 않는다.

## 10. 후속 방향: 노트북 없이 ESP32에서 CAN 제어

2026-10-22 사용자 요청을 반영했다. 노트북은 초기 진단·개발 때 사용하고,
후속 운전에서는 ESP32가 CAN 명령 생성과 응답 처리를 맡는 방향으로 계획한다.
보드 추천 후보는 아래 §11에 추가했다. Wi-Fi/BLE 등 상위 통신 방식은 아직 결정하지 않았다.

```text
조작기 또는 휴대폰(선택) → Wi-Fi/BLE 등 → ESP32
                                         │ TWAI TX/RX
                                   CAN 트랜시버
                                         │ CAN H/L
                                   MKS CAN 2대
```

ESP32-S3는 내장 TWAI 컨트롤러와 외부 트랜시버로 Classic CAN에 접속할 수 있다.
CAN 트랜시버 내장 개발보드를 사용하면 별도 모듈의 중복 구매를 피한다.
보유 ESP32의 칩·노출 핀·트랜시버 유무·3.3V 로직 호환성을 먼저 확인한다.
GPIO를 CAN H/L에 직접 연결하지 않는다.

추가 구매 후보는 TWAI 지원 ESP32 개발보드 1개, 호환 트랜시버 1개,
24V 입력을 지원하는 5V DC-DC 전원 1개, 케이스·단자·배선 1세트,
현장 운전 버튼 1세트다. 무선 조작기는 보유 장비와 조작 방식을 정한 뒤 검토한다.
USB-CAN은 초기 진단용이며 ESP32 단독 운전 중 상시 연결할 필요가 없다.
ESP32부터 바로 시작하는 경우에는 진단 기능과 펌웨어 준비가 추가로 필요하다.

무선 단절과 CAN 단절을 별개로 다룬다. ESP32가 계속 상태 조회·heartbeat를 송신하면
상위 무선 연결이 끊겨도 드라이버 측 보호가 동작하지 않을 수 있다.
따라서 상위 명령 유효기간 만료 시 ESP32의 로컬 정지·운전 허가 해제,
재접속·리셋 후 명시적 재시작, 오래된 명령 폐기를 후속 펌웨어 요구로 둔다.
정지 시간과 만료 시간은 아직 확정하지 않는다. 물리 급전 차단 장치는 유지한다.

기존 T0~T9 뒤에 ESP32의 조회·단축 운전 재현 시험과,
무선 단절·ESP32 리셋·CAN 단절을 구분한 복구 시험을 추가한다.
PC와 ESP32가 동시에 동작 명령을 보내지 않도록 시험별 명령 송신 주체를 정한다.

근거: [Espressif ESP-IDF v5.4.4 ESP32-S3 TWAI](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/peripherals/twai.html),
Overview / Signal Lines and Transceiver / Alerts, 2026-10-22 확인.
이는 구조·부품 후보 계획이며 펌웨어 구현·설치·실물 구동은 미수행이다.

### 14.3 이후 시험 단계에서 준비할 것

| 품목 | 수량 | 준비 시점 |
|---|---|---|
| 홈 스위치+고정부·검출 플래그 | 축당 1개, 총 2세트 | 원점복귀 시험. 입력 규격·기계 검출 구조 확정 후 |
| 온도계/접촉 온도센서 | 1대/세트 | 반복 운전·발열 시험 전, 보유 장비 사용 가능 |

추가 CAN 트랜시버·LILYGO 대안 보드/강압기/외함은 현재 Waveshare CAN-U 선택과 중복되므로 신규 구매 목록에서 제외한다. 나머지 4축 모터, 그리퍼, 감속기, 로봇 링크, RobStride/ROS2 장비는 이후 기구·성능 설계 단계다. 안전 차단 모델이나 고정 방식의 미확정을 전체 준비 완료로 취급하지 않는다. 새 주문·결제·장바구니·펌웨어·실물 작업은 수행하지 않았다.

## 15. 부품 도착 전 준비

사용자가 CF888.021을 **1m × 수량1**로 변경하고 정지 시간 문제 수정과 펌웨어 준비를 계속하도록 지시했다. [도착 전 준비 계획](002-before-arrival-preparation-plan.md)과 [정지 시간 수정·코어 준비007](007-stop-timing-and-firmware-preparation.md)을 따른다. 초기 조작은 휴대폰 웹 화면이며 실제 장치 연결·업로드·실물 시험과 부품 없는 코어 시험을 구분한다. 기존 엑셀/PDF의3m 표기는 선택 변경 전 이력이다.
