# ST3 — 휴대폰 제어 요청과 단일 CAN 소유자 연결 준비

2026-10-23. 사용자: 모델링은 Claude/PrintForge에서 다듬고 Codex는 제어에 집중. 상태: 구현 전 연결 설계 초안. L2/L4·신규 구현 시험 NOT_RUN. 부품 없는 개발을 우선하며 현재 app의 비활성 상태는 유지한다.

## 현재 확인과 우선순위

기존 ST2의 codec/정지 코어/StopLink/TWAI와 ESP32-S3 빌드는 준비돼 있다. 휴대폰 HTML은 모의 시안이다. 다음 단위는 먼저 **장치 없는 제어권·요청 검증 코어**, 다음 정상 CAN actor와 정지 인계, 마지막 SoftAP/HTTP/WS 연결 순서다. 6축 CAD의 길이·감속비·관절각을 아직 모터 제어 상수나 IK에 넣지 않는다. 당장은 명시적1축/2축 벤치 프로필과 고정100펄스 시험을 기준으로 한다.

정본: 웹/운전 계약004, UI005, 수용 사례006. 시간 계약은007/008 및 실제 ST2를 우선한다. 이전004/006의100ms 재조회·1600ms 정지 총시간을 새 구현에 복사하지 않는다. 정상 운전 조회의 응답/신선도 후보와 정지 확인 슬롯은 다른 계약이며, 실물 응답 상한이 미승인이면 운전 허가를 거절한다.

## 실제 코드에서 확인한 연결 주의점

`StopLink`는 정지 한 episode 전용이며 생성자에 I/O가 없다. 자체 port 재초기화·수신·송신·최종 close를 소유하고 terminal 인스턴스를 재사용하지 않는다. 정상 운전 actor와 동시에 같은 CanPort/TWAI를 poll하는 구조를 만들면 안 된다. 정지 성공이후 driver는 닫혀 있으므로 이전 운전 큐를 그대로 재개할 수도 없다.

정상 actor→정지 인계는 별도 설계/검토가 필요하다. 하나의 supervisor task만 transport를 소유하고, 일반 TX를 닫고 미처리 의도를 폐기한 뒤 실제 격리 결과를 통해 StopLink로 넘어간다. 인계 중 실패/결과불명은 Fault다. StopLink의 격리를 이미 완료했다고 가정하는 성공 입력은 금지한다. 정지 동안 웹 keepalive/상태 송신은 가능하지만 CAN keepalive/백그라운드 조회는 송신하지 않는다. 최종 정지 결과는 core 단독이 아닌 `StopLink.state()`와 close 결과로 판정한다.

## 첫 구현 단위: 장치 없는 요청 검증 코어

입력은 파서가 형식 검증한 요청·현재 단조시각·현재 운전 snapshot이다. 출력은 CAN frame 대신 수락/거절 및 제한된 intent다. 생성자/시험은 네트워크·TWAI·GPIO에 접근하지 않는다. JSON 입력 검증은 이 코어 바깥 adapter의 책임이며, 추후 parser 시험과 구분한다.

- 관찰자와 운전 소유자를 구분한다. 정상 관찰자의 정지는 제어권 없이도 허용하며 잘못된 세션/출처는 거절한다.
- 제어권은 boot/session/lease 세대에 결속한다. 새 요청 seq만 전진시킨다. keepalive200ms/만료800ms는004의 후보를 따른다. `now >= deadline`이면 만료이며 늦은 keepalive로 살리지 않는다.
- 운전 허가는 축별이며 보기 탭 전환으로 이전하지 않는다. 실물 프로필/정지·관측/오류 상태는 신뢰 가능한 supervisor snapshot으로만 전달하고 웹 요청의 승인 플래그는 신뢰하지 않는다.
- 이동표는 boot/lease/축/state revision/만료와 결속해 한 번만 소비한다. 동일 request/seq 재전송은 실행0회, 캐시가 비워져도 이전seq를 실행하지 않는다. 캐시 용량·ID wrap·세대 재사용 불명은 거절한다.
- intent도 대기 중 만료될 수 있으므로 소비와 실제 송신 직전에 현재 시각·세대·상태를 재검사한다. 별도 FIFO로 이동을 쌓거나 재접속 뒤 자동 재전송하지 않는다.
- 정지/통신오류/운전 중 lease 만료는 허가·이동표·미출고 이동을 폐기한다. 이미 송신된 이동을 취소했다고 표시하지 않고 정지 episode를 요청한다. 반복 요청으로 정지 기한을 연장하지 않는다.
- 첫 버전의 이동 의도는 선택축 D0/D1·100펄스·속도5·acc2로 제한한다. raw CAN·전류·임의속도/각도 입력·다축 동시 이동·토크해제는 이 단위의 출력에 넣지 않는다. 미확인 위치는0이 아니라 invalid로 전달한다.

## 구현 순서와 완료 기준

| 순서 | 산출물 | 완료 기준 |
|---|---|---|
| ST3-1 | 요청 검증 코어와 fake clock/snapshot 시험 | 아래 경계 사례 실행, 실제 CAN 출력 경로 없음 |
| ST3-2 | 정상 CAN actor·운전 supervisor·정지 인계 | 단일 소유자, 실제 TX완료 기준, generation/기한/응답 검증, StopLink 정상/실패 경로 통합 |
| ST3-3 | SoftAP·HTTP/WS·휴대폰 화면 연결 | 실제 snapshot 표시, 단일 제어권, 잠금/이탈 만료, 재접속 자동운전 없음, parser/Origin 검증 |
| ST3-4 | ESP32 타깃 재빌드 | 신규 실제 운전/정지 실행 경로가 archive뿐 아니라 최종 ELF에 링크됨을 확인. 실물 미승인 기본값 유지 |

각 구현 단위는 별도 저장 계획/L2와 구현/L4를 거친다. ST3-1은 L2 최대2회/L4 최대2회, 작성자와 비작성자 검토를 분리한다. 지금 문서는 코드 검토 통과나 연결 완료를 주장하지 않는다.

## 먼저 고정할 호스트 경계 사례

1. 두 세션 동시 제어권 요청: 하나만 수락, 관찰자의 정지는 허용.
2. 만료 직전/정각/직후 keepalive와 move: 정각부터 만료; 정지·만료 우선.
3. 축1 허가로 축2 이동, 이전 boot/lease/revision ticket, 같은seq/요청 중복: 이동 의도0회.
4. move 수락 직후 stop·오류·만료, intent 출고 직전 시각 전진: 미출고 이동0회.
5. 큐·결과 캐시 포화/ID 소진/시계 역행: 재실행·묵시적 허가 없음.
6. 실물 프로필 미승인, 2축 중1축 미관측: 허가 거절, 누락축 자동 제외 없음.
7. 종료/재접속/재부팅 뒤 과거 intent·허가 복원0회. 목표 위치와 관측 위치 구분.

모델링 파일은 이번 단위에서 수정하지 않는다. 업로드·전원 인가·실물 이동·프린터·구매는 수행하지 않는다. 모델링 쪽 실제 치수가 정해지면 별도 axis calibration 입력으로 도입하며 시각 CAD 각도를 모터 각도로 바로 사용하지 않는다.
