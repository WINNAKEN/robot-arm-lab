# ST3-1 — bounded offline control gate

2026-10-23. L2 R2 PASS (MET6/UNMET0); implementation snapshot in progress. Definitive health/readiness and phase rules are in L2 R1 disposition below. Scope: request gate only; no app integration, CAN frames, JSON parser, network, SDK or physical motion. Existing 004/007/008 contracts and ST2 remain unchanged. This does not complete ST3 supervisor/transport handoff.

## Ownership and interface

New `robot_gate` standalone C++17 component, no dynamic allocation/I/O/clock calls; one serialized owner. Caller supplies uint64 monotonic milliseconds and trusted Snapshot on every entry. Public typed Request is untrusted; adapter must validate wire version, Host/Origin and decoding separately. Gate registers at most two sessions through trusted API; session IDs allocated monotonically internally, never reused. Boot ID is supplied once by trusted boot service and must be nonzero/unique across boots (randomness not proven here). Lease/ticket/intent IDs are monotonic nonzero uint64, exhausted counters fault rather than wrap. No boot/reset API to resurrect state.

Snapshot: strictly monotonic revision, two fixed active-axis entries, active count 1 or 2, approved profile, ready/stopped proof, enabled/observed/valid flags, current moving/stop/fault. Repeated revision must have bytewise-semantic identical fields; changed content with same revision or revision rollback faults. Missing/duplicate/invalid axis profile faults. Snapshot booleans are trusted supervisor attestations, never copied from request. Position is not represented; invalid observations are never represented as zero. Any changed revision revokes unconsumed ticket/intent. New observation timestamps also require revision increment. A published stop/fault or loss of readiness while armed/reserved requests stop.

## State and transitions

Two sessions maximum with globally generated IDs; disconnect removes session, owner disconnect requests stop if owned. No result cache: accepted-envelope seq high-water per session survives rejected commands and lease release, no ID reuse, strictly increasing request_id too. Authenticated current-boot request advances both watermarks once freshness validated, even if operation subsequently rejected; rejected duplicate/old envelope does not advance either. Zero/max counters rejected/fault as documented. No replay creates output. Acquire produces fresh lease ID and deadline now+800; renew requires current lease and fresh envelope, at exactly deadline expiry wins. Acquiring while another owner exists fails. Expiry always clears authority and requests stop, even idle owner; late renewal cannot reacquire. Stop is accepted from any registered current-boot session, independent of lease/sequence, and coalesces in separate priority latch with original first stop timestamp; old/invalid boot/session rejected. Stop clears lease, arm, ticket, pending intent immediately. No operation clears stop/fault; new gate lifetime required after future supervisor explicit recheck (outside this unit).

Arm selected axis only if entire active profile approved/observed/ready and selected axis enabled proven; it records permission only, does NOT emit enable/F3. Single armed axis; changing armed axis is rejected. Actual enable/disable handshake belongs ST3-2. Arm is not inferred from UI selection or raw enabled flag. Ticket issue requires ownership+armed axis+stable snapshot and no reservation. Lifetime500ms; ticket binds boot/session/lease/axis/revision/deadline. Single ticket slot; second issue rejected until expiry. Move consumes current ticket exactly once, validates D0/D1 and fixed preset100 pulses/speed5/acc2, creates single pending intent, sets reservation immediately. No second movement while pending/taken reservation; take_intent rechecks same current snapshot/authority/revision/expiry with >= boundary. Invalid/revised/expired pending intent clears it, revokes arm and requests stop. A taken intent cannot be fetched again; reservation persists until trusted complete callback with matching intent ID, new higher revision and explicit stopped observation. Completion never silently re-arms; permission revoked, explicit arm needed again. Transport submit-time revalidation beyond returned intent is ST3-2 responsibility; returned intent includes dispatch_before=min(ticket expiry,lease expiry), revision and lease binding. Caller must serialize take+submission and enforce deadline immediately pre/post I/O. No claim offline gate can stop externally retained copies.

## Priority and failures

Every entry first advances clock, ingests snapshot, and handles fault/stop/lease expiry before request. Equal-time stop/expiry wins. Stop latch consumed through take_stop() once; repeated stop does not regenerate or move initial deadline. Snapshot update in absence of request via tick. Clock reversal, deadline addition overflow, ID exhaustion, malformed trusted snapshot produce latched fault and stop intent, clear all permissions. end-of-call guard rechecks invariant and time bounds (same supplied fake time; wall-clock duration cannot be checked here). `take_intent` is the sole movement output. Error/stop snapshot exposed through Status with revision/error/stop_started_at/reserved. No FIFO/cache allocation; 2 sessions+1 ticket+1 move+1 stop fixed capacities. Session capacity rejection causes no authority change.

## L2 R1 disposition — topology identity frozen, proof predicates split

L2R1 NEEDS_ATTENTION: active topology/profile identity was insufficiently frozen. Corrected before implementation; awaiting L2R2, no code yet.

Construction takes const Config copied internally: boot_id, active_axes[2]/count, and nonzero profile_id. Valid configurations are [1], [2], [1,2] exactly; immutable for gate lifetime. Every trusted Snapshot carries same profile_id/count/axis order; any difference (even higher revision) is a latched ProfileChanged fault/stop. Snapshot approved is a changing runtime attestation only, not permission to change identity. Actual configuration changes require external maintenance and fresh boot/gate; constructor cannot verify uniqueness across boots. Invalid config faults immediately. Gate is noncopyable/nonmovable.

Split predicates: healthy = approved profile, all active observations valid, no supervisor fault/stop and exact frozen profile identity. stopped = healthy plus supervisor stopped=true and moving=false. Arm/ticket/move/take require stopped AND selected-axis enabled; acquire requires stopped (enabled not required). Readiness is explicit `ready` attestation, required for acquire/arm/ticket/move/take but may legitimately be false during physical motion. Supervisor snapshot does not directly encode gate-derived reserved state.

Reservation phases: Pending (move accepted, output not taken) versus Dispatched (intent taken). Any revision change in Pending invalidates the intent and requests stop (including ordinary fresh observation); caller must not update snapshot between take and submit without revalidation. In Dispatched, higher-revision healthy moving=true/ready=false is expected and does not by itself fault; stopped=false is not a generic unhealthy predicate. Lease expiry, invalid observation, approval loss or supervisor stop/fault always stop even Dispatched. Unexpected moving=true while armed/ticketed/Pending requests stop. Plain Ready health changes revoke arm/ticket; no sticky automatic permit resurrection. Completion requires Dispatched ID exact, Snapshot revision strictly greater than dispatch revision, healthy+stopped+ready and selected axis enabled. Invalid completion revokes and requests stop; valid completion clears reservation and arm without restoring permission. No completion accepted in Pending.

Envelope uint64 sequence/request_id maxima use checked counters: nonzero strict greater accepted, reaching max faults instead of later wrap; invalid enum values rejected. Stop authentication intentionally does not consume/rely on seq/request freshness so a valid observer's repeated stop always coalesces; it never emits movement. Session creation/removal are trusted adapter lifecycle methods, never web-provided arbitrary IDs. `Status` reports snapshot revision independently of command rejection detail; errors do not fake sensor revision increments.

Additional acceptance: higher revision changed profile_id/count/list faults for both idle and lease-owned paths; initial [1]/[2]/[1,2] supported; unapproved valid config yields normal denial; dispatched healthy moving state allowed; pre-dispatch moving invalidates; completion cannot run pending or equal revision. Existing tests remain as in main plan. L2R2 is final planned round; no implementation until independent GO.

Per-axis observation contains `moving` as well as enabled/valid: any moving nonselected active axis while permission or reservation exists requests stop; expected motion is restricted to selected axis after Dispatched. Aggregate moving must equal OR(active axis moving) and stopped proof cannot coexist with moving; inconsistent trusted snapshot faults. An idle gate with moving observation does not grant acquisition. Snapshot comparison checks explicit fields, never struct padding bytes.
