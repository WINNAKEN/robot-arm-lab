# MKS CAN 2축 배선·명령 실행 가이드

작성: 2026-10-22 · 문서 v1.0 · 대상: 고정한 무부하 모터 2개

**부품 수령 후 이 문서의 순서대로 확인한다. 현재 완료한 것은 자료 대조와 프레임 산술 검산이며, 배선·통신·모터 시험은 미실시다.** 실제 제품의 펌웨어와 단자를 확인하기 전에는 예시 명령을 전송하지 않는다.

**아직 필요한 준비:** ESP32의 CAN 송수신·휴대폰 웹 펌웨어는 구현하지 않았다. 보드만 연결해 이 표를 휴대폰에서 보낼 수 있는 상태는 아니다. 먼저 P3/P4의 제어 규칙과 화면을 설계·구현하고, 아래 무부하 시험을 수행할 수 있는 송수신·정지·로그 기능을 준비해야 한다.

**통전 전 보류 조건:** 퓨즈와 주차단장치의 실제 정격·배선, 모터 정격에 맞는 전류 설정, 브래킷과 베이스 고정이 결정되지 않으면 전원 인가 단계로 넘어가지 않는다. 세트에 들어 있는 최소 5A 퓨즈나 전원장치의 최대 10A를 그대로 채택하지 않는다.

### 첫날 순서

1. 무전원 상태에서 제품 라벨·단자 기록 → 제조사 자료와 실물 대조. About 화면은 첫 기동 때 기록.
2. 완전 무전원에서 1축 전원·CAN 배선 및 종단 검사.
3. 정지 상태에서 물리 급전 차단·복귀 확인 → 한 대씩 ID·속도·모드·전류 확인 → 필요할 때만 별도 무부하 교정.
4. 읽기 응답 확인 → 정지 명령 확인 → 작은 이동 1회 → 정지·단절 시험.
5. 전원을 끄고 축2를 추가 → 종단 재설정 → 축별 시험. 동시 시작은 후속 단계.

## 2. CAN 배선도 — 먼저 1축, 이후 2축

**실물 단자의 H와 L 표시를 따라 연결한다.** 이 도식은 케이스의 위·아래 또는 좌·우 배치를 뜻하지 않는다. CAN선에는 모터 전원을 흘리지 않는다.

### 1축 시험

```text
Waveshare CAN-U                         MKS axis 1
H  ==================================  H
L  ==================================  L
CAN 120R: ON                            CAN 120R: ON
```

### 2축 시험

```text
Waveshare CAN-U           MKS axis 1           MKS axis 2
H  ===================== H ================== H
L  ===================== L ================== L
CAN 120R: ON              CAN 120R: OFF        CAN 120R: ON
```

H/L은 같은 꼬임쌍의 두 심이다. 중간 축1에서 축2로 이어 가며, 긴 별모양 분기는 만들지 않는다. 두 전선을 한 단자 구멍에 임의로 밀어 넣지 않는다. 수령 단자의 복수 도체 허용 여부와 맞는 접속 방법을 확인하고, 별도 접속점이 필요하면 드라이버 바로 가까이에 짧게 만든다. 탈피 후에도 단자 가까이까지 꼬임을 유지한다.

| 연결점 | 사용 단자 | 이번에 연결하지 않을 단자 |
|---|---|---|
| Waveshare | CAN H → MKS H, CAN L → MKS L | RS485 A+/B−, SH1.0 IO1/IO2/3V3/GND |
| MKS 축1·축2 | H, L | EVCC / EGND / IN_1은 초기 CAN 시험에서 미사용 |
| 실드 | 초기 짧은 고정 벤치에서는 양 끝 절연 | H/L 또는 임의 GND 대체선으로 사용하지 않음 |

**GND 정정:** Waveshare의 외부 CAN 단자는 H/L뿐이다. 내부 CAN 기준 SGND는 절연되어 있고 외부로 나오지 않는다. 전원 −나 SH1.0 GND를 별도 CAN 기준선으로 연결하지 않는다. MKS 두 대의 전원 GND는 §3처럼 같은 DC 0V로 돌아간다. 실드 양 끝 절연은 초기 벤치의 잠정안이며, 장기 섀시 접지·노이즈 성능을 검증한 상태는 아니다.

### 종단 설정과 무전원 검사

| 구성 | Wave CAN 종단 | 축1 종단 | 축2 종단 | 전체 H–L 측정 목표 |
|---|---|---|---|---|
| 1축 | ON | ON | 미연결 | 약 60Ω |
| 2축 | ON | OFF | ON | 약 60Ω |

- Wave CAN 종단은 H1/R19. 회로상 1–2 연결은 120Ω ON, 2–3은 OFF다. 실물의 **CAN 120R/NC 표시**를 확인한다. RS485용 H2와 혼동하지 않는다. 기본값은 NC로 안내돼 있다.
- MKS는 CAN 120Ω 점퍼 장착=ON, 제거=OFF. 내장 종단 두 개가 확인되면 외장 120Ω을 더 달지 않는다.
- 전원 출력과 USB를 모두 분리하고 잔류전압이 없을 때 H–L 저항을 잰다. 약 120Ω은 종단 한 개, 약 40Ω은 종단 세 개의 가능성을 확인할 단서다. 60Ω만으로 통신 합격은 아니다.
- MKS p18의 특정 USB-CAN 단독 연결 그림은 모터 종단 미장착을 안내한다. 어댑터 조건이 명시되지 않아 그대로 적용하지 않았다. 본 구성은 Waveshare를 사용하는 선형 버스의 양 끝 각 120Ω 설계다. 근거: TI SLLA270 §4.5.

## 3. 전원 배선 기능도와 단자표

**아래는 보호·차단 위치를 정한 기능도다. K1의 실물 단자 번호와 퓨즈 용량을 확정한 제작 회로는 아직 아니다.** K1 주접점·보조접점과 정지/복귀 버튼의 회로는 선택품 자료에 맞춰 별도로 완성해야 한다.

```text
PSU + (12~24V)
  +--- F0 ----------------------------- Waveshare +
  |
  +--- FM --- K1 ---+--- F1 ----------- MKS1 V+
                    +--- F2 ----------- MKS2 V+

PSU - / 0V --------+------------------- Waveshare -
                   +------------------- MKS1 GND
                   +------------------- MKS2 GND

F0/FM/F1/F2: protection ratings TBD
K1: motor-power disconnect, device/pins TBD
```

F0는 제어기 분기, FM은 모터 급전, F1/F2는 각 축 분기 보호의 설계 위치다. 실제 채택 수량·정격·배선 보호 협조는 미정이다. K1이 모터 전원을 끊어도 Wave에는 전원이 남는 구성으로, 정지 원인 표시를 유지하려는 제안이다. 자동 잠금 2채널 릴레이 사진을 확정품으로 채택하지 않았으며 두 접점을 병렬로 연결해 정격을 늘리지 않는다.

| 부품 단자 | 연결 | 확인할 사항 |
|---|---|---|
| Wave 전원 + / − | F0 뒤 + / DC 0V | 보드 입력 7–36V. 이번 공통 전원은 MKS 때문에 24V 이하 |
| MKS V+ / GND | 축별 보호 뒤 + / DC 0V | MKS 허용 12–24V. PSU의 32V 최대치로 설정하지 않음 |
| MKS COM / EN / STP / DIR | 초기 CAN 운전에 미사용 | COM은 CAN 기준 GND가 아님. bus mode의 enable은 CAN 명령으로 제어 |
| MKS A+ A− / B+ B− | 각각 모터 한 상 | MT 출고 결선 우선. 선색 추측 금지, 통전 중 분리 금지 |
| MKS EVCC / EGND | 미사용 | 보조 5V/20mA. ESP32 급전용으로 쓰지 않음 |

MKS p10 그림의 방향은 모터 4핀 단자가 위, OLED/버튼이 아래다. 그때 왼쪽 위부터 **EVCC, EGND, IN_1, H, L**, 오른쪽 위부터 **V+, GND, COM, EN, STP, DIR**이다. 실물이 다르면 사진·라벨을 대조한 뒤 진행한다.

### USB 연결과 독립운전 전환

| 상황 | Wave USB | Wave DC 단자 급전 | 작업 순서 |
|---|---|---|---|
| 업로드 / USB 점검 | 연결 | 분리 | 전체 전원 OFF → Wave DC 급전선 분리·절연 → USB 연결 |
| 휴대폰 독립운전 | 분리 | 연결 | USB 분리 → 전체 전원 OFF에서 DC 연결 → 극성 확인 → 전원 ON |

Waveshare 공식 FAQ는 **USB와 단자 전원을 동시에 공급하지 말 것**을 안내한다. MKS 별도 급전 여부와 무관하게 Wave 자체의 두 입력을 동시에 사용하지 않는다. 케이블을 바꿀 때마다 완전 무전원 상태에서 작업한다.

WAGO형 커넥터 하나의 구멍은 내부에서 서로 연결된다. +와 0V는 반드시 별도 커넥터로 분배한다. 18AWG 구매선의 사용 범위·주간선 허용전류는 길이·단자·퓨즈와 함께 정하며, PSU가 10A라는 이유로 모든 구간의 10A 사용을 승인하지 않는다. PSU 접지/섀시 단자를 DC−와 같은 것으로 간주하지 않는다.

## 4. 한 대씩 초기 설정하기

아래 단계는 §1의 전원·고정 조건과 ESP32 송수신 도구가 준비된 뒤 수행한다. 기본 ID가 같을 수 있으므로 **축2를 설정할 때는 축2만 연결·급전**한다.

| 순서 | 할 일 | 기록 / 통과 조건 |
|---|---|---|
| S1 | 전원 OFF에서 전원 극성·H/L·고정·종단 검사 | 단락 없음, H–L 약60Ω, 케이블 장력 없음 |
| S2 | 한 대만 켜고 About·라벨 기록, 정지 상태 물리 차단·복귀 확인 | HW/FW와 CAN 모델 확인. 모터측 급전 차단 확인 후 새 이동 없이 복귀. 이후 교정/이동으로 진행 |
| S3 | 화면에서 축1 CanID=1 / 축2 CanID=2 설정 | 각 축을 따로 설정하고 라벨 부착. 두 축 모두 500k 확인 |
| S4 | 모터 명판에 맞게 전류 확인·설정 | 모터 상전류와 DC 전원 전류제한은 별도 기록 |
| S5 | Mode=SR_vFOC, MStep=16 확인 | 기본 CR_vFOC와 구분. 읽기로 설정값 재확인. OPEN 모드에서 교정하지 않음 |
| S6 | 교정 여부 확인, 필요한 경우에만 무부하 교정 | p20/35/103 대조. 최초 드라이버 장착·상순서 변경 때 재교정. 회전 공간 확보 후 실행·성공 확인 |
| S7 | 응답·완료 알림 활성, 동기 기능 사용 안 함 | §6 참고. 재부팅 뒤에도 값 확인, 대기 명령 실행 금지 |
| S8 | 위치·속도·enable·운전 상태 읽기 | 올바른 ID/DLC/체크섬의 응답과 로그 확보 |
| S9 | 주기 조회와 heartbeat 설정·읽기 확인 | 초기 후보: 축별 조회100ms, 보호1000ms. 실기 시간 검증 전 확정 아님 |

교정은 회전을 수반하며 화면의 Cal 기능으로도 실행할 수 있다(p20/35). 비OPEN 모드·무부하에서 수행한다. CAN 교정 명령은 `80 00`에 checksum을 붙이며, **축1 DATA=80 00 81 / 축2 DATA=80 00 82, DLC3**이다. 응답 `80 S C`에서 S=0 교정 중, 1 성공, 2 실패다. 읽기 버튼에 자동으로 묶지 않는다. 출고 교정이 확인되고 조립·상 결선을 바꾸지 않은 MT 조립품을 이유 없이 다시 교정하지 않는다. 교정 이력이 없거나 최초 장착·상순서 변경 이력이 있으면 p103 조건에 따라 재교정한다.

### CAN 송수신 공통 설정

| 항목 | 값 |
|---|---|
| CAN 종류 | Classical CAN, 표준 11bit ID, 데이터 프레임, RTR 아님 |
| 속도 | 500 kbit/s — 제어기와 두 드라이버 동일 |
| CAN ID | 축1=0x001, 축2=0x002. 초기 시험에서 ID0 브로드캐스트 미사용 |
| 데이터 길이 | 최대8바이트. 표의 DLC는 checksum 포함, CAN ID 제외 |
| 다바이트 순서 | Big-endian: 상위 바이트부터 |
| checksum | ID1/2에 대해 (CAN ID + checksum 이전 DATA 바이트 합) & 0xFF |
| Wave 내부 핀 | TX GPIO15 / RX GPIO16. 펌웨어 작성 때 적용, 외부 점퍼선 추가 아님 |

예: **CAN ID=0x001, DLC=2, DATA=31 32**. 마지막 32는 0x01+0x31의 합이다. ID를 DATA 앞에 붙이지 않고 UART 헤더도 붙이지 않는다. 표의 수치는 모두 16진수다. 실제 byte 값이 00/FF인 정상 checksum도 있지만, checksum 검사를 생략하는 기능은 사용하지 않는다.

CAN ID나 속도는 첫 연결에서는 화면 메뉴로 설정하는 편이 명확하다. CAN으로 ID1을 ID2로 바꾸는 참고값은 **ID=0x001, DLC4, DATA=8B 00 02 8E**다. 변경 응답이 이전/새 ID 중 어느 쪽인지 원문이 불명확하므로, 화면 확인 후 새 ID의 설정 읽기로 확인한다. 첫 기동이나 설정 변경 자체가 무조건 축을 비활성 상태로 만든다고 가정하지 않는다.

## 5. CAN 읽기 명령표

각 행에서 송신할 축의 CAN ID와 DATA를 함께 선택한다. 표는 ID1/2 전용이다. 응답은 수신 CAN ID·명령코드·DLC·checksum을 확인한 뒤 해석한다. C는 응답 자체로 계산한 checksum이다.

| 읽기 | DLC | 축1 DATA | 축2 DATA | 근거 |
|---|---|---|---|---|
| 버전 | 2 | `40 41` | `40 42` | p33 |
| 누적 엔코더 위치 | 2 | `31 32` | `31 33` | p27 |
| 실제 속도 | 2 | `32 33` | `32 34` | p27 |
| enable 상태 | 2 | `3A 3B` | `3A 3C` | p29 |
| 운전 상태 | 2 | `F1 F2` | `F1 F3` | p70 |
| Mode | 3 | `00 82 83` | `00 82 84` | p32 |
| 동작 전류 | 3 | `00 83 84` | `00 83 85` | p32 |
| MStep | 3 | `00 84 85` | `00 84 86` | p32 |
| CAN 속도 | 3 | `00 8A 8B` | `00 8A 8C` | p32 |
| CAN ID | 3 | `00 8B 8C` | `00 8B 8D` | p32 |
| 응답 설정 | 3 | `00 8C 8D` | `00 8C 8E` | p32 |
| heartbeat 시간 | 3 | `00 98 99` | `00 98 9A` | p32 |
| 동기 플래그 | 3 | `00 4A 4B` | `00 4A 4C` | p32 |

### 응답 해석

| 명령 | 응답 형식 | 의미 / 축1 예시 |
|---|---|---|
| 40 버전 | 40 [교정·HW] [FW...] C | 원문에 FW 길이 모순. raw DLC/바이트를 기록하고 About와 대조 |
| 31 위치 | DLC8: 31 [signed48, 6바이트] C | 1회전=16384카운트. 0 예시: `31 00 00 00 00 00 00 32` |
| 32 속도 | DLC4: 32 [signed16 rpm] C | 정지 예시: `32 00 00 33` |
| 3A enable | DLC3: 3A state C | 0=비활성, 1=활성. 활성 예시: `3A 01 3C` |
| F1 상태 | DLC3: F1 state C | 0=조회실패, 1=정지, 2=가속, 3=감속, 4=정속, 5=원점복귀, 6=교정 |
| 00 설정 읽기 | [설정 코드] [값] C | 앞의 00은 응답에 붙지 않음. 전류=uint16 mA, ID=uint16, heartbeat=uint32 ms |

Mode가 SR_vFOC이면 축1 응답은 `82 05 88`, MStep16이면 `84 10 95`, 500k이면 `8A 02 8D`다. F1의 정상 운전 상태 조회는 SR 계열 모드에서 사용한다.

지원하지 않는 설정 읽기는 **code FF FF C, DLC4**를 반환한다(p32). 예를 들어 축1의 heartbeat 미지원은 `98 FF FF 97`이다. 큰 숫자 설정값으로 해석하지 않는다. 무응답·길이 불일치도 성공으로 간주하지 않는다.

엔코더 위치는 6바이트 signed 값으로 부호 확장해야 한다. 원문의 CW/CCW 부호 설명이 예시와 다르므로 실제 관찰한 **D0/D1 방향과 위치 증가/감소**를 기록한다. 위치 0이나 부팅 직후 위치를 기구의 원점으로 간주하지 않는다. 명령 목표 위치와 실제 읽은 위치를 구분한다.

## 6. 설정·허가·통신 단절 보호

아래 일반 설정 응답은 **code S C, DLC3**, S=1 성공 / 0 실패다. 설정 성공 응답을 받고 가능한 항목은 읽기로 재확인한다. 교정의 상태값은 §4처럼 별도다.

| 작업 | DLC | 축1 DATA | 축2 DATA | 근거 |
|---|---|---|---|---|
| SR_vFOC | 3 | `82 05 88` | `82 05 89` | p35 |
| MStep16 | 3 | `84 10 95` | `84 10 96` | p37 |
| 500k, 참고 | 3 | `8A 02 8D` | `8A 02 8E` | p40 |
| 응답+완료 알림 활성 | 4 | `8C 01 01 8F` | `8C 01 01 90` | p41 |
| heartbeat1000ms | 6 | `98 00 00 03 E8 84` | `98 00 00 03 E8 85` | p44 |
| 동기 비활성 | 3 | `4A 00 4B` | `4A 00 4C` | p96 |
| 모터 enable | 3 | `F3 01 F5` | `F3 01 F6` | p71 |
| 모터 disable | 3 | `F3 00 F4` | `F3 00 F5` | p71 |

전류 쓰기는 모터 정격을 확인한 뒤 정할 항목이므로 고정값 명령을 넣지 않았다. CAN 속도 변경 응답이 이전/새 속도 중 어느 쪽인지 원문에 명시되지 않아 화면 설정을 우선한다.

enable은 축에 유지 토크를 주고, disable은 축을 느슨하게 만든다. **disable을 감속 정지로 대신 쓰지 않는다.** 두 명령의 성공 응답은 모두 축1 `F3 01 F5`, 축2 `F3 01 F6`이므로, 성공 응답만 보고 enable 상태를 추측하지 말고 3A로 읽는다. bus mode에서 EN 단자는 enable을 통제하지 않는다(p71).

### heartbeat 적용 규칙

- 제조사 기본 보호 시간은 0, 즉 꺼짐이다. 1000ms는 이번 시험의 후보값이며 제조사 보장 정지시간이 아니다.
- 설정 시간 동안 호스트 명령을 받지 못하면 드라이버가 급정지하도록 설명돼 있다. 전용 주기 heartbeat 코드가 따로 필요한 것은 아니다. ESP32가 각 축에 정상 F1/31 조회를 주기 전송하는 방식으로 계획한다.
- **조회 주기100ms는 축별 후보**다. 주기 송신·응답 확인이 준비된 뒤 1000ms 보호를 켠다. 값을 쓰기만 하고 주기 송신 없이 움직이지 않는다.
- 전원 재인가 후 저장 여부와 어떤 수신 패킷이 타이머를 갱신하는지는 원문에 충분히 명시되지 않았다. 매 부팅 때 설정·읽기를 확인하고 실기 재부팅 시험으로 검증한다.
- 휴대폰이 끊겨도 ESP32가 CAN 조회를 계속하면 드라이버 heartbeat는 만료되지 않을 수 있다. **휴대폰 조작 세션 만료 감시와 로컬 정지 처리는 ESP32에서 별도로 필요하다.**

### 초기 제어기의 필수 동작

1. 기동·재접속 때 축 상태부터 읽고 이전 이동 요청은 폐기한다. 자동 운전 허가·이전 이동 복원 금지.
2. 이동 요청은 한 번씩 처리한다. 송신 완료·응답·실제 정지를 별도 상태로 기록한다.
3. 응답 누락 시 상대 이동을 자동 재전송하지 않는다. 정지 요청 후 상태를 확인한다.
4. 화면 종료/백그라운드/무선 단절을 ESP32의 세션 만료로 감지한다. 브라우저 종료 이벤트에만 의존하지 않는다.
5. 동기 플래그 4A=0을 초기 기준으로 사용한다. 4A00이 과거 대기 명령을 지운다는 보장은 없으므로, 동기용 명령을 저장한 이력이 있으면 이 절차에 섞지 않는다. 초기 시험에서는 실행 코드4B를 보내지 않는다.

## 7. 첫 이동과 정지 명령

**한 축만, 무부하, 고정 완료, 정지 경로와 주기 조회 준비 후 수행한다.** 속도값5·acc2·100펄스는 낮은 속도 시험 후보이며 실제 최소 안정 속도와 정지 거리는 아직 측정하지 않았다.

| 작업 | DLC | 축1 DATA | 축2 DATA |
|---|---|---|---|
| D0 방향 100펄스 | 8 | `FD 00 05 02 00 00 64 69` | `FD 00 05 02 00 00 64 6A` |
| D1 방향 100펄스 | 8 | `FD 80 05 02 00 00 64 E9` | `FD 80 05 02 00 00 64 EA` |
| FD 감속 정지, acc4 | 8 | `FD 00 00 04 00 00 00 02` | `FD 00 00 04 00 00 00 03` |
| FD 즉시 정지, acc0 | 8 | `FD 00 00 00 00 00 00 FE` | `FD 00 00 00 00 00 00 FF` |
| F7 소프트웨어 급정지 | 2 | `F7 F8` | `F7 F9` |

근거: p78–80 FD, p71 F7. 두 방향 행을 연속 실행하는 왕복 스크립트가 아니다. 첫 이동 완료·실제 위치를 확인한 뒤 다음 명령을 사용자가 별도로 요청한다. 표의 DATA 마지막 바이트까지 포함해 전송한다.

### FD 데이터 구성과 이동 단위

| 바이트 | 의미 |
|---|---|
| 1 | FD 명령 |
| 2 | bit7=방향, bits6..4=0, bits3..0=속도 상위4bit |
| 3 | 속도 하위8bit |
| 4 | acc, 0은 즉시 변경, 1..255는 클수록 빠른 가감속 |
| 5..7 | uint24 펄스 수, Big-endian. 100=00 00 64 |
| 8 | checksum |

**1.8° 모터 + MStep16이면 100펄스=11.25°**다. 일반식은 `펄스 수 × 기본 스텝각 ÷ MStep`이며 실물 스텝각 확인 전 각도를 확정하지 않는다. p103은 별도 모터의 폐루프 호환 조건으로 1.8°를 명시한다. 수령품이 다르면 수학 환산만으로 계속하지 말고 모터·드라이버 호환성을 재확인한다. 엔코더16384카운트/회전과 FD의 펄스 단위는 다르다. 1.8°/16분할의 100펄스는 엔코더 약512카운트 변화에 해당한다.

speed5는 MStep16 기준 5rpm 후보다. 매뉴얼 p68–69의 속도 환산 조건을 따른다. 초기 시험에서는 MStep을 임의로 바꾸지 않는다. D0/D1은 실물에서 관찰한 방향으로 라벨링한다.

### 응답과 멈춤의 의미

| 응답 | 해석 |
|---|---|
| FD S C, DLC3 | 0 실패, 1 시작, 2 완료, 3 리미트 정지, 5 동기 데이터 저장 |
| 축1 FD 예시 | 시작 `FD 01 FF`, 완료 `FD 02 00`, 실패 `FD 00 FE` |
| 축2 FD 예시 | 시작 `FD 01 00`, 완료 `FD 02 01`, 실패 `FD 00 FF` |
| F7 S C, DLC3 | 0 실패, 1 성공. 성공: 축1 `F7 01 F9`, 축2 `F7 01 FA` |

완료 알림에는 8C 설정과 도달 임계값95가 영향을 준다. 완료가 없으면 F1/31을 조회하고 멈추며 **같은 FD를 재전송하지 않는다.** F7/FD 정지는 CAN이 전달돼야 동작하고, F3 disable은 유지 토크를 해제하며, K1은 모터 급전을 차단한다. 서로 대신하는 기능이 아니다. 정지 응답 뒤 실제 회전·속도·위치를 확인한다. 제조사는 1000rpm 초과에서 급정지를 권장하지 않는다. 이번 저속 예시를 고속 운전에 그대로 적용하지 않는다.

## 8. 실물 시험 순서와 기록

**각 단계가 통과해야 다음으로 진행한다.** 처음부터 두 축 동시 이동이나 로봇 링크를 연결하지 않는다. 결과 칸의 현재 상태는 모두 NOT_RUN이다.

| 단계 | 수행할 일 | 다음 단계로 갈 조건 |
|---|---|---|
| T0 수령·보호 | §1 정격·버전·고정·차단·퓨즈 확정 | 빈 필수 항목 없음, 적합한 멀티미터·정지 수단 준비 |
| T1 무전원 1축 | §2·3 배선, 종단·극성·단락 확인 | 약60Ω, 잘못된 극성·노출 도체 없음, USB/DC 중복 없음 |
| T2 정지 상태 차단 | 한 대 기동·상태 관찰 후 물리 차단/복귀 시험 | 모터측 급전 차단 확인, 복귀만으로 움직이지 않음. 교정 전 확인 |
| T3 설정 | §4 한 대씩 ID/속도/전류/모드/교정 확인 | 실제 버전 기록, 설정 읽기와 화면 일치 |
| T4 읽기·정지 | §5 읽기, 정지 상태에서 F7 응답 확인 | 정확한 ID/DLC/checksum, 위치·속도·운전 상태 해석 가능 |
| T5 보호 설정 | 축별 주기 조회와 heartbeat1000ms 설정·읽기 | 응답·보호 설정 확인. 실제 정지시간 합격은 아직 아님 |
| T6 첫 이동 | enable 확인 → D0 100펄스 1회 | 시작·완료/상태·위치변화·실제 정지 기록. 이상 없을 때만 D1 별도 |
| T7 동작 중 정지 | 같은 제한된 이동 중 FD 정지/F7 각각 시험 | 실제 동작 중 적용됐는지 확인. 명령 전에 이미 끝났으면 미검증 |
| T8 단절·복구 | 별도 이동 조건 확정 후 대상 축 송신 중단, 무선 세션 만료 별도 시험 | 이 가이드의 100펄스로 1초 heartbeat 정지 판정 불가. 조건 확정 전 보류 |
| T9 동작 중 차단 | T2를 통과한 장치로 제한된 이동 중 급전 차단 | 실제 급전 차단·회전 정지 관측, 복귀만으로 움직이지 않음 |
| T10 축2 추가 | 전체 OFF → 축1종단OFF·축2ON → 각 축 T1~T9 | 명령한 축만 반응, 두 축 위치/응답 구분, 오류 없음 |

T7/T9는 100펄스 이동이 짧아 시험 신호 전에 끝날 수 있다. T8의 heartbeat 시험은 더 명확한 제한이 있다. 1.8°/16분할/5rpm에서 100펄스의 정속 이동 시간은 약0.375초이며 가감속을 포함해도 이번 후보는 1초 보호 만료 전에 끝날 수 있다. **이 프리셋으로 heartbeat 정지 성능을 판정하지 않는다.** 공간·전류·회전량을 재검토해 충분히 긴 별도 시험 조건을 확정하기 전에는 T8을 보류한다. 무선 세션 만료 시험도 만료 시점에 실제 이동 중인지 확인한다.

정지·차단 시점이 이동 중이었는지 로그와 관찰로 확인하며, **이미 멈췄다는 사실을 보호 기능 통과로 쓰지 않는다.** 이 가이드에서 임의로 펄스 수를 늘리지 않는다. CAN 케이블을 통전 상태에서 뽑는 대신 시험용 소프트웨어로 송신을 멈추는 방식부터 사용한다.

무선 단절 시험에서는 ESP32가 정상 CAN 조회를 유지하는 경우도 확인해 휴대폰 세션 만료 정지가 별도로 작동하는지 본다. CAN 단절 시에는 F7 전달도 실패할 수 있으므로 물리 차단 수단이 준비되어 있어야 한다. 시험 전류제한·퓨즈·급전 차단 회로가 미확정이면 T0에서 보류한다.

T8의 CAN heartbeat 시험에서는 대상 축의 F1/31 조회를 포함해 모든 송신을 중단하고 수신·외부 관찰만 한다. 관측하려고 조회를 다시 보내면 보호 타이머를 갱신할 수 있다. F7이나 물리 차단으로 중단했다면 그 조치를 기록하되 heartbeat 자체에 의한 정지로 판정하지 않는다.

## 9. 문제 해결·근거·남은 작업

| 증상 | 먼저 확인 |
|---|---|
| 아무 응답 없음 | 전원, H/L 교차, 500k 일치, ID 중복, 종단, 표준 DATA 프레임 설정. 무응답 상태에서 반복 enable/이동 금지 |
| 설정 응답이 FF FF | 미지원 파라미터 형식인지 확인. HW/FW와 해당 버전 문서 대조 |
| 두 축이 함께 반응 | 기본 ID1 중복 의심. 전체 OFF 후 한 대씩 ID 재확인 |
| FD status5 | 동기 대기 상태 가능성. 4B로 실행하지 말고 동기 설정·대기 이력부터 확인 |
| 완료 알림 없음 | 8C·95·운전 상태·위치 확인. 같은 상대 이동을 다시 보내지 않음 |
| 정상 checksum인데 오류 | ID·DLC·버전·mode·원문 필드 확인. checksum 통과는 명령 호환성 보장이 아님 |
| H–L 약60Ω인데 통신 실패 | 60Ω은 저항 검사만 통과. 실제 속도·프레임·오류 상태·배선 접속을 별도 확인 |

### 원문 오류와 이번 가이드의 처리

- p33 버전 응답은 DLC5/Bytes3–4와 firmVer[3] 표기가 서로 맞지 않는다. 원시 응답과 About를 기록하며 펌웨어 버전 파서를 추측하지 않았다.
- p27의 엔코더 CW/CCW 부호 설명이 예시와 다르다. D0/D1과 실제 위치 증가·감소로 기록한다.
- p78 FD 속도 설명 문장 일부가 표와 다르다. 표와 정상 예시를 따르고 초기 속도값5를 사용했다.
- p86 F4 음수 예시는 데이터9바이트로 DLC8을 초과하며 checksum도 맞지 않는다. 최초 이동표에서 F4를 제외하고 FD 펄스 이동을 채택했다.
- p18의 USB-CAN 단독 연결 종단 예시는 이번 Waveshare 회로 조건과 구분했다. §2에 선택한 종단 구성을 명시했다.
