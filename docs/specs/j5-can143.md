# J5 한 축 조회 시험 준비 — non-U 보드 지원

2026-11-12 KST. 사용자 보드는 **ESP32-S3-RS485-CAN(U 없음)**, 대상 모터는 **J5 MKS CAN**이다. 모터 전원은 계속 OFF로 유지한다. 이번 변경은 로컬 소프트웨어 준비이며 ESP 업로드·실제 CAN 요청·모터 급전/운전이 아니다.

## 펌웨어 확인 결과

COM7 USB 및 ROM에서 ESP32-S3 revision0.2를 확인했다. app0 앞4KiB의 저장 메타데이터는 project=arduino-lib-builder, version=6683a0d, build=Jun24 2024 13:24:30, IDF=v5.1.4-358-gbd2b9390ef-dirty다. app1은 앞4KiB만 전부FF다. 현재 실행 슬롯·실제 스케치 기능·공장 펌웨어 여부·전체 이미지 무결성은 확정하지 않는다. 우리 준비 진단의 project=robot_arm_readonly / IDF5.5.6과 같다고 확인된 것은 아니다. 원ROM자료와판정은outputs/esp-stored-slot-142/에 보존했다.

## 이번에 바뀐 준비 코드

기존 진단은 CAN-U 이름만 허용했으나 이제 Board::WaveshareCan으로 non-U를 별도 지원한다. 기존 enum 값과 CAN-U/다른 모델 거절 정책을 유지한다. 모델 이름이 확인돼도 보드 리비전·모터드라이버 HW/FW·실제 ID/CanRate·핀·배선·전원투입 동작 관측은 필요하다. 자료의 TX15/RX16·500kbit/s는 기대 제약이며 현재 실물 측정값이 아니다.

ReadyForReview도 hardware_approved=false다. 기본 diagnostic app의 kPhysicalReadApproved=false/static_assert와 CAN 비활성 동작은 유지한다. 빌드된 기본 이미지는 검토용 **비활성 후보**이며 플래시·CAN 조회 실행 허가가 아니다. source/host/build 결과는outputs/j5-nonu-profile-prep-143/에 기록한다.

빌드가 만든 sdkconfig는 원본 설정과 구분해 outputs/j5-nonu-profile-prep-143/native-config/에 보관한다. 이번 기본 빌드의 flash_size=2MB는 실제 보드 확인값이 아니다. 원ESP 파티션표는16MiB 영역까지 선언하지만 실제 flash geometry·부팅/파티션 보존·복구 방식은 아직 검증하지 않았다. 이 후보의 flasher_args나 생성 로그의 업로드 예시를 그대로 실행하지 않는다.

`src/bench/j5_can141.py plan`의 최신 차단 이유는 BLOCKED_UNCONFIRMED_PROFILE이다. 실제ID/baud/GPIO=null, 기본frames=[]다. `--candidate-id 1` 또는2는 31/32/F1/3A 네 읽기 프레임의 오프라인 미리보기이며 주소 설정이나 송신을 하지 않는다. J5라고 ID5를 넣지 않는다. 141/142 당시의 'CAN-U만허용' 상태와 clock은 역사 기록이며 그 원자료를 수정해 소급PASS로 만들지 않는다.
