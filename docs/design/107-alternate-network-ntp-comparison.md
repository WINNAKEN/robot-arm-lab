# 107 — 동일 PC의 별도 인터넷 경로 비교 제안

2026-11-02. **제안만 / 네트워크 전환·새 질의 미실행**. 106에서 활성 QoS 제한 정책은 비었고 W32Time의 NTP 허용 필터가 확인됐다. 실제 drop 이벤트·NIC 출고는 미확정이다. 다음에는 같은 로컬 PC를 휴대폰 핫스폿 등 별도 인터넷 경로에서 비교해 호스트와 경로를 더 구분한다.

## 영향과 역할

사용자가 로컬 PC의 Wi-Fi를 원래 연결 A에서 휴대폰 핫스폿 B로 잠시 바꾼 뒤 다시 A로 돌린다. 인터넷·SSH 연결이 잠깐 끊기고 휴대폰 데이터를 소량 쓸 수 있다. 사용자가 두 번의 연결 전환과 원래 연결 복구를 직접 수행할 수 있을 때 진행한다. 연결 암호나 공유기·방화벽·VPN 설정을 에이전트가 바꾸는 절차는 아니다.

에이전트는 각 상태에서 경로·IP·네트워크 프로필·기존 전체 바인딩을 읽고, 같은 비관리자 NTP 클라이언트와 고정 목적지 `52.231.114.183:123`으로 최대3회씩 질의한다. 설치·새 서비스·수집 설정 변경·resync·Set-Date·NTP provider 변경·어댑터 필터 토글·실물CAN·SDK/native는 없다. 이 제안은 새 시뮬45분 승인이 아니다.

## 비교 순서

1. 사용자가 전환/복구 가능한 상태인지 확인한다. 다른 원격 실행/Kit 작업이 없음을 확인한 뒤 A0의 경로·프로필·NIC GUID·바인딩 맵과 기존 NTP3표본을 새107 폴더에 저장한다. 옛104/106 질의를 지우거나 동일 예산으로 재발사하지 않는다.
2. 사용자가 B로 전환하고 준비됐다고 알려주면 같은 NIC·필터 상태, 다른 gateway, 네트워크 프로필을 기록한다. 목적지 IP는 바꾸지 않고 같은 요청 형식/timeout으로3표본을 읽는다. 원시 요청·응답·송수신 시각·출처·origin 일치·NTP 유효성을 보존한다.
3. 사용자가 원래 A로 돌아가면 경로·프로필·바인딩 복원을 읽고 A1의3표본을 저장한다. 복구가 안 됐거나 연결이 모호하면 추가 시험 대신 상태를 알려 원래 연결 복구를 우선한다.
4. 서버 간헐 응답이라는 혼재 요인을 줄이기 위해 기존 isaacpc에서 같은 NTP 주소의 읽기 전용3표본을 대조할 수 있다. SDK/원격 시간서비스 변경·옛099 실행과는 별개이며 실제 SSH 수행 여부/손실을 기록한다. 대조가 불가능하면 그 한계를 남긴다.

표본별 수신 timeout은2초, 각 네트워크 상태의 질의는1묶음/최대3회다. 이 제한은 작업전체10분마다 중단하거나 예산을 다시 승인받는 조건이 아니다. 전환 대기 동안 새 네트워크 질의를 반복하지 않으며, 인터페이스/바인딩/목적지 불일치나 부분 결과는 UNKNOWN으로 남긴다.

## 해석 한계

A0 실패·B 유효응답·A1 실패가 재현되고 같은 NIC/바인딩/클라이언트 및 비교 가능한 프로필과 원격 서버 대조가 확인되면 원래 인터넷 경로의 관여를 뒷받침한다. 네트워크 프로필이나 경로 조건이 함께 바뀌면 혼재 요인을 명시한다. 공유기 자체/상위 회선/ISP·호스트의 조건부 정책 중 특정 장비를 단독 원인으로 확정하지 않는다.

B에서도 실패하면 호스트의 유일 원인을 확정하지 않는다. 두 경로 모두 NTP를 제한하거나 서버가 불안정할 가능성을 남긴다. 결과에 따라 방화벽·VPN·공유기·필터를 자동 변경하지 않는다. 후속 수리는 관측 근거와 구체 변경 범위를 제시한 뒤 해당 승인 범위에서 진행한다.
