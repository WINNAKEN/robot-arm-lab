각 시험은 초기 상태, 가짜 단조 시각, 입력 이벤트 순서, 예상 CAN TX 목록, 최종 상태, 화면 이벤트를 명시한 fixture로 만든다. 구현 함수의 내부 분기 수를 그대로 기대값으로 삼지 않는다. 경계값은 만료 직전/정각/직후를 포함한다. 유효하지 않은 프레임도 수신됐다는 이유로 last_valid_rx를 갱신하지 않는다.

Rmax 전제가 성립하지 않아 오래된 응답이 새거래의 정상창 안에 들어오는 경우, CAN에 요청nonce가 없어 원리적으로 구별 불가능할 수 있다. O26을 이 반례까지 해결한 시험으로 확대하지 않는다. 그런 장치/전제에서는 운전 프로필을 승인할 수 없으며 응답지연·RX서비스 상한은 별도 실물H11의 수용 전제다. host fixture의epoch태그만으로 선로프레임에없는식별자를발명하지않는다.

## 4. 기록 형식

한 시험마다 case_id, 문서/프로필/빌드 식별, 입력 fixture, 실제 TX/RX, 기대/관측 상태, 오류 원인, PASS/FAIL/NOT_RUN, 근거 파일을 남긴다. 실행하지 않은 항목은 PASS로 바꾸지 않는다. 현재 O/H 시험은 모두 PLANNED이며 UI 디자인 렌더 결과만 별도 증거에 존재할 수 있다.
