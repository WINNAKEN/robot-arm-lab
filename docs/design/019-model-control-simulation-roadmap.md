# 후속 목표 — 레이아웃에서 제어·Isaac Sim·강화학습으로

2026-10-23 사용자 방향 기록. 현재 진행 중인 설정 재확인·휴대폰/ESP32 준비를 유지하며, 모델링 담당이 확정한 레이아웃을 기준으로 후속 작업한다. 현재 단계는 목표/연결 기준이며 시뮬레이터 설치·월드 제작·학습·실물 실행 완료가 아니다.

## 진행 순서

1. **레이아웃 기준 확정:** 편집 원본 파일과 리비전, 베이스·링크·공구 좌표계, J1~J6의 부모/자식 링크와 실제 회전축 원점·방향·영점·가동 범위를 고정한다. 그리퍼는 별도 관절/구동기 정의로 추가한다. 모델링 담당의 최신 확정본 경로를 확인한 뒤 제작 기준으로 채택한다.
2. **모터/관절 매핑:** 관절마다 모터·드라이버 식별자, 감속비, 회전 부호, 모터 영점/관절 영점, 엔코더 단위와 출력축 각도의 변환, 속도·가속도·토크 한계를 기록한다. 먼저 현재2축 시험에서 부호·스케일·영점과 실제 응답을 검증한 뒤 확장한다.
3. **물리 모델:** 링크별 질량·무게중심·관성, 충돌 형상, 관절 제한·마찰·감속부 유격과 구동기 모델을 정의한다. 미측정 값은 가정/출처/허용 범위를 명시하고 실측 값과 구분한다. CAD 좌표의 mm를 시뮬레이션의 m로 변환한다.
4. **Isaac Sim 월드:** 베이스/작업대/바닥, 로봇 articulation, 공구·그리퍼 및 목표 물체를 구성한다. 관절별 단독 회전, 영점, 제한, 순기구학과 충돌을 대조하고 재현 가능한 로드/reset 상태를 만든다. 호환 파일 형식과 Isaac 버전·하드웨어 요구는 구현 시 공식 자료와 로컬 GPU 환경을 확인해 결정한다.
5. **강화학습 환경:** 우선 목표점 도달 같은 작은 과제를 택해 관측·행동·보상·종료·reset·난수 seed·평가 조건을 정의한다. 이후 물체 집기·놓기와 물리 오차/지연 변화를 추가한다. 학습 성공률은 별도 평가로 기록하며 시뮬레이션 정책의 실제 모터 전송은 별도 수용 단계를 거친다.

## 공통 좌표·구동 계약

- 관절 상태의 공통 표현은 출력축 기준 rad, 속도 rad/s, 길이 m. 사용자 화면의 도/모델링 mm는 경계에서 명시적으로 변환한다.
- 감속비 N>0, 방향 s∈{-1,+1}이면 `q_joint = q_joint_zero + s * (theta_motor - theta_motor_zero) / N`. 모터 각도와 출력축 각도를 같은 값으로 보내지 않는다.
- 관절 제한, 좌표계, 감속비, 단위·부호·영점의 정본을 하나로 두고 CAD/시뮬레이션/제어가 이를 참조한다. 파일 경로와 해시/리비전, 가정·실측 상태를 함께 남긴다.
- 현재 CAN 구현은1/2축 시험용이다. 향후6축+그리퍼 매핑은 프로토콜 범위·스케줄링·대역폭·정지/제어권 정책을 별도로 검토한다. 학습 행동을 현재 CAN raw 명령으로 바로 연결하지 않는다.

## 다음 착수에 필요한 입력

모델링 확정본의 원본/조립 구조와 축별 회전축 표, 실제 모터·드라이버 사양, 관절별 감속비와 가동 범위, 링크 질량·재질·실측 계획, 사용 GPU 환경. 미정 항목은 미정으로 두고 값·성능·제작 승인을 추정해 채우지 않는다.
