# 부품 도착 전 준비 계획

작성일: 2026-10-22. 현재정지시간은007이대체한다. C++ codec·정지코어와호스트시험구현,프로젝트전용컴파일러준비완료. 실제ESP32통신/웹연결/target빌드·실물시험은미완료다. 상세검증상태는 `.dev/firmware-core-evidence/validation.md`.

목표는 부품이 도착했을 때 연결 방법과 시험 순서를 새로 고민하지 않고, 한 축의 통신 확인부터 시작할 수 있게 준비하는 것이다. 최초 범위는 고정한 무부하 모터 2개이며 로봇 링크·감속기·원점복귀는 후속 단계다.

## 1. 이번에 정리한 기준

- 제어기: 선택한 Waveshare ESP32-S3-RS485-CAN-U 1개. ESP32가 두 모터의 CAN 명령 송신과 응답 처리를 맡는다. PC는 개발·업로드·로그 확인 때 사용하고 상시 연결은 목표 구성에 포함하지 않는다.
- 구동기: 주문 완료한 MKS SERVO42D CAN MT 2세트. 실제 HW/FW 버전·상전류·단자 구성은 수령 시 기록한다.
- CAN선: 사용자가 **CF888.021, 길이 1m × 수량 1**로 변경했다. 구매 완료 확인은 아니다. 공식 회로 대조 결과 Wave 외부 CAN은 H/L만 노출되며 내부 SGND는 절연되어 있다. 전원/확장 GND를 CAN 기준선으로 추가하지 않는다. 초기 벤치는 실드 양 끝 절연 잠정안으로 두고 장기 섀시 접지는 후속 설계한다. 케이블은 배치 치수 확정 전 자르지 않는다.
- 전원: 선택한 WANPTEK EPS3210. 최초 모터 공급은 기존 계획의 24V 이하 범위에서 검토하며 전류 제한·퓨즈값은 실물 정격 확인 후 확정한다. 전원장치 최대 10A와 모터 상전류는 서로 다른 값이다.
- 초기 조작 방식은 **휴대폰 웹 화면으로 사용자 선택 완료**. ESP32가 제공하는 화면에 접속해 축별 이동·정지를 조작하는 방향이다. ESP32 AP 직접 접속을 첫 설계 기본안으로 정했다. 물리 급전 차단 기능은 화면의 정지 버튼과 별도로 설계한다.
- 미래 6축+그리퍼를 고려해 축별 설정 구조를 계획하되, 이번 수용 시험은 2축에 한정한다. 다른 종류의 그리퍼를 같은 프로토콜로 가정하지 않는다.

## 3. 연결 설계에서 결정할 내용

기능 구성은 다음과 같다. 최신 H/L·전원 단자명과 종단 연결은 가이드003에 정리했다. K1의 실물 단자 회로와 퓨즈 정격은 아직 미확정이다.

```text
휴대폰 웹 화면 ─ Wi-Fi ─ ESP32 CAN-U
                                      │
                         CAN 버스 ─ 모터 1 ─ 모터 2

DC 전원 ─ 차단·보호·분배 설계 ─ 모터 1/2 전원
       └ ESP32 전원 경로: 차단 범위와 USB 급전 조건 대조 후 확정
```

- ESP32 → 모터 1 → 모터 2의 배치를 먼저 스케치하고 실제 거리와 여유 길이를 기록한다. 최신 선택1m는 두 구간과 단자 여유를 합친 전체 확보 분량이다. 두 구간을 각각1m로 해석하지 않는다. 구간별 절단 길이는 실물 배치 후 정한다.
- 종단 설계는 1축: Wave ON/축1 ON, 2축: Wave ON/축1 OFF/축2 ON으로 문서화했다. MKS 특정 USB-CAN 단독 예시의 예외와 이번 Wave 회로의 차이는 가이드 §2에 기록했다. 실물 무전원 H–L 약60Ω 확인은 미수행이다.
- 절연 CAN 측 기준선과 전원/USB/섀시 접지를 구분한다. 단자 이름만 보고 서로 연결하지 않고 제조사 회로와 실제 기판 버전을 대조한다.
- 모터 급전 차단 뒤 ESP32 상태 확인을 유지하는 분기안을 가이드 §3에 반영했다. Wave USB와 DC 단자 동시급전은 제조사 FAQ에서 금지하므로 전원 OFF에서 한 경로만 선택하도록 전환 순서를 명시했다.
- DC 차단 장치·복귀 논리·퓨즈 협조와 고정판은 첫 실물 구동 전 해결할 항목이다. 현재 채택 보류인 2채널 자동 잠금 릴레이를 설계 확정품으로 넣지 않는다.

## 4. 제어 규칙 추천안

1. 전원을 켜면 조회 가능한 정지 상태로 시작한다. 축 ID·버전·상태를 확인하기 전에는 이동을 허가하지 않는다.
2. 초기 조작은 작은 상대 이동 한 번씩으로 제한한다. 누르고 있는 동안 계속 도는 조그, 자동 반복, 자동 원점복귀는 정지 검증 이후 단계로 둔다.
3. 사용자가 이동을 명시적으로 요청해야 동작한다. 응답 대기 중 중복 이동 명령을 쌓지 않고, 일반 이동 재전송이 중복 실행을 만들지 않도록 명령별 재시도 규칙을 정한다.
4. 무선 조작 명령의 유효기간과 CAN 응답 제한시간을 별도로 관리한다. 화면이 백그라운드로 가거나 연결이 끊어지면 이전 이동을 계속 허가하지 않는 방향으로 설계한다.
5. 무선 단절 때 ESP32가 CAN 조회를 계속하면 드라이버의 통신 단절 보호가 작동하지 않을 수 있다. ESP32의 로컬 정지와 운전 허가 해제를 따로 설계하고, CAN 자체 단절 보호와 별개로 시험한다.
6. 오류·리셋·재연결·정지 버튼 복귀만으로 이전 명령을 재실행하지 않는다. 대기 명령을 폐기하고 명시적 상태 확인·재허가 후 새 명령만 받는다.
7. 명령 송신 완료, 드라이버 응답, 실제 회전 정지는 각각 기록한다. 화면의 정지 버튼 성공 표시만으로 물리 정지를 합격 처리하지 않는다.

시간 제한·속도·각도·전류는 초기 후보와 확정값을 구분한다. 기존 계획의 100ms/1,000ms 등의 값은 실물 보호 성능 보증이 아니다.

### 4.1 첫 휴대폰 화면의 기능 범위

조작 방식만 사용자 확정이며 아래는 첫 화면의 설계안이다. 비연결 HTML 시안은 작성했으며 실제 장치를 제어하는 화면/펌웨어 구현과 동작 검증은 미수행이다.

| 화면 영역 | 첫 버전 기능 | 동작 규칙 |
|---|---|---|
| 연결 상태 | 휴대폰–ESP32 연결과 축별 CAN 응답 상태를 따로 표시 | Wi-Fi 연결만으로 모터가 준비됐다고 표시하지 않음 |
| 축 선택·상태 | 축 1/2 선택, 응답으로 읽은 위치·운전 상태·오류 | 마지막 응답 시각과 오래된 값 여부 표시. 명령 목표값을 측정 위치로 표시하지 않음 |
| 이동 설정 | D0/D1,100펄스·speed5·acc2 고정 이동 | 첫 버전은 자유 각도·속도 입력을 보류. 한 번씩 실행하며 중복 적재·자동 재전송 금지 |
| 운전 허가·정지 | 상태 확인 후 명시적 운전 허가, 모든 축 소프트웨어 정지 | 정지 명령 전송·응답·정지 확인을 구분. 물리 급전 차단은 별도 장치 |
| 기록 | 최근 명령·응답·오류 보기, 기록 내보내기 | 페이지 새로고침은 운전 명령 재실행을 일으키지 않음 |

- 한 번에 한 조작 세션만 이동 권한을 갖도록 설계한다. 다른 탭/휴대폰의 접속이 현재 권한을 자동으로 빼앗지 않게 한다.
- 화면 종료·백그라운드 전환·Wi-Fi 단절을 다룬다. 브라우저의 종료 알림만 믿지 않고 ESP32가 조작 세션의 유효기간을 검사해 정지 요청·운전 허가 해제를 수행하는 구조를 계획한다. 제한시간은 후속 명령표·시험 기준에서 정한다.
- 다시 접속하면 상태 확인부터 시작하며 이전 명령을 자동 복원하지 않는다. 첫 화면에는 연속 조그·자동 반복·원점복귀·원격 인터넷 운전을 넣지 않는다.
- 화면의 축 목록은 축별 설정에서 가져오는 방향으로 설계해 향후 확장을 준비하되 현재 시험·표시는 2축으로 제한한다.

## 5. 개발 준비 범위

- 개발 환경 후보는 ESP-IDF v5.5.6 + legacy TWAI + SoftAP + esp_http_server/WS다. Waveshare 예제와 버전 고정된 공식 API를 대조했다. 근거는 `_research/esp32-firmware-sdk-20261022.md`. 선택 근거와 한계는004 §8에 있으며 실제 설치·빌드 검증은 미수행이다.
- CAN 송수신, MKS 프레임 변환, 축 상태 관리, 조작 인터페이스, 로그를 나누는 구조를 계획한다. 축 ID 1·2는 설정으로 관리하고 7축 고정 배열이나 공통 명령 지원을 미리 가정하지 않는다.
- 로그에는 시각, 축 ID, 송신/응답, 명령, 상태·위치, 오류, 재시작 원인을 남길 계획이다. 수령 후 실물 버전과 펌웨어 빌드 식별자를 함께 보존한다.
- 모의 데이터로 프레임 처리와 화면 흐름을 시험할 수 있지만 CAN 전기 특성·트랜시버·모터 호환·발열·정지시간 검증을 대신하지 않는다.
- 호스트 도구 설치, 예제 실행, 펌웨어 작성·플래시, MKS 드라이버 펌웨어 변경은 이번에 수행하지 않았다. 드라이버 업데이트를 첫 단계의 기본 작업으로 넣지 않는다.

| 전류 제한·퓨즈값·실제 온도와 정지시간 기준 | 전원 10A 및 세트의 최소 퓨즈 5A로 자동 결정하지 않음 |
| 고정판·나사 깊이·배선 간섭 | 무부하 시험도 모터 고정 후 진행 |

도착 첫날 목표는 **수령 확인 → 무전원 점검 → 한 대의 기동/교정 여부 확인 → CAN 읽기 확인**이다. 교정은 필요한 경우 별도 수행한다. 작은 이동과 정지는 앞 단계 확인 후 진행하며 두 축 동시 운전은 이후로 둔다. 최신 상세 순서·기록 양식은 [배선·명령 가이드 §4~8](003-wiring-and-can-command-guide.md)을 따른다.

## 7. 근거와 상태

- 받은 Makerbase 공식 `User Manual/V1.0.9/MKS SERVO42&57D_CAN User Manual V1.0.9.pdf`와 버전별 README. 실제 수령 버전 확인 전 명령 지원 확정 아님.
- [Waveshare 보드 문서](https://www.waveshare.com/wiki/ESP32-S3-RS485-CAN): 직접 열람은403, 후속 P1에서 공식 검색 인덱스의 인터페이스/FAQ와 내려받은 공식 회로를 대조했다. H/L·SGND·USB/DC·GPIO15/16 근거는 가이드003과 배선 근거 파일에 기록. 실물 PCB 개정과 예제/SDK 버전 대조는 남아 있다.
- [Espressif ESP32-S3 TWAI 문서](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/twai.html): 2026-10-22 열람 경로는 v6.1로 표시. Classic CAN 및 버스 오류/복구 API 확인. 이것을 프로젝트 SDK 채택으로 해석하지 않는다.
- [Espressif HTTP Server 문서](https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32s3/api-reference/protocols/esp_http_server.html): 보드 내 웹 조작 화면의 가능성 참고. 프로젝트 채택 버전에서 재검증한다.
