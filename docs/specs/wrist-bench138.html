이번 결과: 준비 코드 · 오프라인 시험실제 급전 · 통신 · 구동: NOT_RUN

조립 사진은 기구 조립 보고입니다. 드라이버가 RS485형인지 CAN형인지, 전원·모터 정격·감속비·실제 단자 위치는 아직 확인되지 않았습니다. 아래는 기존 구매 기록의 SERVO42D RS485 MB + Waveshare ESP32-S3-RS485-CAN을 기준으로 한 준비안입니다.

처음에는 한 축만. 나머지 두 축은 전원 OFF와 통신선 물리 분리를 유지합니다. 현재 보드의 공장 펌웨어가 무엇인지 모르므로, USB를 연결하기 전에도 모터 전원과 A/B 버스를 분리합니다. USB만 꽂으면 기존 펌웨어가 무조건 무동작한다고 가정하지 않습니다.

01 · 짧은 1축 RS485 시험 결선 — 단자 이름 기준

MKS 제품 문서의 12–24V는 모델 범위이며 이번 현품의 설정 승인이 아닙니다. Waveshare DC 입력(7–36V) 범위를 모터 전압으로 쓰지 않습니다. USB와 Waveshare DC 입력은 동시에 연결하지 않습니다.

절연 기준선

Waveshare 통신부 SGND와 논리 SH1.0 GND는 구분합니다. 외부 A/B 단자만 보이는 보드에 일반 USB–RS485 그림의 GND선을 임의로 추가하지 않습니다. 기준선 필요성은 현품 회로와 절연을 대조해 결정합니다.

아래는 확장 방향입니다. 공장 기본 주소가 모두 1일 수 있으므로 세 대를 동시에 연결하지 않습니다. ID 1/2/3은 배치 제안이며, 한 대씩 현품 주소를 확인·설정한 기록이 필요합니다. 이번 소프트웨어는 주소를 바꾸거나 스캔하지 않습니다.

현재 짧은 1축 RS485 준비안: MKS V1.0.9 p19는 모터측 종단 점퍼를 끼우지 않도록 안내합니다. Waveshare도 기본 NC 준비안입니다. 이를 긴 다중 RS485 버스에 그대로 적용하지 않습니다.

CAN 양 끝 각120Ω이면 무전압 H–L 측정은 대략60Ω입니다. 이는 저항 검사이며 통신·정지 수용이 아닙니다. 이 CAN 검사표를 현재 단독 RS485에 적용하지 않습니다. 기존 CAN actor는2축 준비물이므로3축 실물 통합·정지 검증이 별도로 필요합니다.

3 / 확장용 구조 — 현품 확인·정격 선정 뒤 사용

소프트웨어: 지금은 오프라인으로 실행

src/bench/wrist138/bench.py는 파일과 바이트만 처리합니다. COM 포트를 열거나 장치를 검색하지 않으며 실제 송신 기능이 없습니다.

향후 읽기 전용 ESP32 펌웨어

src/bench/wrist138/firmware/는 기존 로봇 펌웨어와 분리된 준비 타깃입니다. 기본 WRIST138_HARDWARE_PERMIT=OFF에서는 app_main의 명시 UART/USB 초기화와 송신을 하지 않습니다. ROM/부트로더 출력이나 현품에 이미 있는 펌웨어의 동작까지 보장한다는 뜻은 아닙니다.

읽기 중계는 모터 제어기가 아닙니다. 향후 별도 현품 확인·업로드/실행 승인을 거친 허가 분기에서도 READ 주소 opcode만 받습니다. 예: READ 1 31. F3 enable, FD 이동, F7 정지, 교정·설정변경 명령은 모두 거부합니다. jog-plan의 FD 미리보기는 이 중계기로 보내도 실행되지 않습니다.

준비 배선은 UART1 TX=GPIO17 / RX=GPIO18 / RTS=GPIO21, RS485 HALF_DUPLEX입니다. GPIO21을 고정 HIGH로 두지 않습니다. 38400/8N1/native FA–FB는 준비 후보이며 실제 드라이버 설정과 대조해야 합니다. Modbus-RTU 모드나 CAN payload와 혼용하지 않습니다.

각도와 그리퍼 mm를 섞지 않기

motor_deg는 모터축, output_deg는 감속기 출력축입니다. gear_ratio=모터 회전/출력 회전이며 실측 확인 전 미정입니다. rack_mm는 그리퍼 한쪽 랙의 이동량입니다. 대칭 양쪽 랙이면 전체 벌어짐 변화는 그2배이며 별도 항목으로 출력합니다. 실제 피니언 반경과 비율 확인 전 mm 계획도 BLOCKED입니다.

계획기의 모터축5°/5rpm 상한은 오프라인 소프트웨어 상한일 뿐 실물 사용 승인값이 아닙니다. 펄스로 반올림한 뒤에도 상한·실제 여유를 재검사합니다. 시뮬레이션 cap이나 CAD의27:1 가정을 실물 프로필에 복사하지 않습니다.

4 / 실제 포트·플래시·급전·움직임 없음

실물 시험 때의 순서와 기록

  1. 모든 전원 OFF. 잔류 전압·극성·단락·단자명·코일 결선·케이블 장력을 확인합니다. 점퍼와 커넥터는 무전압에서 변경합니다.
  2. 기구를 고정하고 J5를 받칩니다. 전원을 끄거나 enable을 해제하면 중력축이 처질 수 있습니다. 손으로 움직이는 축을 잡아 정지시키지 않습니다.
  3. 한 대만 식별. 다른 두 축은 OFF/버스 분리. 드라이버형·HW/FW·모터 정격·모드·주소·baud·자동홈/자동재개·교정 이력을 기록합니다. 교정 이력이 불명확하면 자동 교정 대신 보류합니다. 조립 기어와 하중을 연결한 채 무심코 CAL을 실행하지 않습니다.
  4. 읽기만 확인. 위치·속도·운전상태·enable의 실제 원시 응답과 화면을 비교합니다. F1=0은 조회 실패이며 정지가 아닙니다. 엔코더 counts는 모터 내부 값이므로 출력축 각도·유격의 측정 결과로 바꾸지 않습니다.
  5. 정지·수동 급전 차단·복귀를 먼저 확인. 실제 관측으로 확인하며 응답 ACK만으로 기계 정지나 정지 시간을 승인하지 않습니다. 통신이 끊기면 소프트웨어 정지 명령도 전달되지 않을 수 있습니다. 차단 복귀만으로 자동 재개하지 않아야 합니다.
  6. 별도 승인된 극소 유한 이동. 방향·중립·여유·전류·고정·정지를 확인한 후 하나의 짧은 이동만 계획합니다. 현재 read-only 중계로는 이동할 수 없으므로 후속 운전 경로와 승인이 필요합니다. 무응답 상대 이동을 재전송하지 않습니다.
  7. 실제 출력 방향·감속비·유격을 관찰. 같은 조건에서 다른 축으로 옮기고, 최종 CAN으로 바뀌면 통신·단절·정지·스케일을 다시 검증합니다.
