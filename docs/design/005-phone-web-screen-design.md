# 휴대폰 웹 화면·첫 펌웨어 설계 요약

2026-10-22 · robot-arm-lab · 화면 시안 / 실제 장치 미연결

## 1. 부품이 오면 사용할 모습

휴대폰을 ESP32가 만든 Wi-Fi에 연결하고 브라우저에서 제어 화면을 연다. ESP32가 화면 제공과 두 모터의 CAN 송수신을 맡는다. 노트북은 개발·업로드·로그 확인 때만 사용한다. **현재는 설계와 비연결 화면 시안이며 실제 펌웨어는 아직 없다.**

```text
Phone -- Wi-Fi AP -- ESP32 CAN-U -- CAN -- Motor 1 -- Motor 2
                         |
                  Local web screen
```

공유기를 쓰는 방식도 가능하지만 첫 설계는 AP 직접 접속이다. AP 방식은 이번 설계의 기본안이며 사용자가 별도로 선택했다고 기록하지 않는다. 인터넷 접속·클라우드·외부 서버가 필요 없는 방향이다. ESP32의 전원은 배선 가이드003의 USB/DC 전환 규칙을 따른다.

첫 수령 점검은 **1축 시험 프로필**, 한 대씩 확인한 뒤 **2축 프로필**을 사용한다. 응답 없는 축을 자동 제외하지 않는다. 프로필 변경은 모터 급전 차단·유지보수 확인 후 재기동하며 이전 운전 허가를 폐기한다. 아래 화면 시안은2축 프로필의 모의 예시다.

| 처음 제공할 것 | 사용 방식 |
|---|---|
| 연결 상태 | 휴대폰–ESP32와 축1·축2 CAN 응답을 각각 표시 |
| 제어권 받기 | 한 탭/휴대폰만 조작. 새 접속은 관찰로 시작 |
| 축 선택 | 축1/축2 상태 보기. 선택만으로 허가를 다른 축으로 옮기지 않음 |
| 운전 허가 | 고정·주변 확인 후 선택축만 명시적으로 허가 |
| 1회 이동 | D0/D1 중 하나, 100펄스·속도값5·acc2 고정 |
| 모든 축 정지 | 화면 아래에 항상 표시. 소프트웨어 명령임을 명시 |
| 기록 | 실제 송신/응답/관측 상태 구분, 최근 기록 확인 |

연속 조그, 자유 각도·속도 입력, 두 축 동시 이동, 자동 원점복귀, 로봇 경로·그리퍼는 뒤로 둔다. 기존 계획의 자유 입력 구상은 삭제한 요구가 아니라 첫 고정 프리셋 검증 이후 단계다.

## 2. 화면에서 구분해야 할 상태

| 표시 | 사용자가 알 수 있어야 하는 것 |
|---|---|
| 대기 / 관찰중 | 연결돼 있어도 아직 이동할 수 없음 |
| 내가 조작 / 선택축 허가됨 | 제어권과 축별 운전 허가는 별도 상태 |
| 이동 요청 접수 | ESP32가 요청을 받았음. 모터가 움직였다는 증거는 아님 |
| 이동중 | 드라이버 시작 응답을 받음. 실제 위치는 응답 값으로 별도 표시 |
| 정지 처리중 | 새 이동 금지, 정지 전달·상태 확인 중 |
| 정지 후 재점검 | 이전 이동 폐기, 새 확인과 허가 필요 |
| 연결끊김 / 값 오래됨 | 마지막 값과 응답 시각 유지. 실제 위치처럼 갱신하지 않음 |
| 정지 미확인 | 화면만으로 정지 보장 불가. 물리 전원 차단 필요 안내 |

전원 차단장치 K1의 상태를 읽는 센서는 현재 정하지 않았다. 화면에 K1 ON/OFF나 물리 정지 완료를 확정 표시하지 않는다. 모터 토크해제는 정지 버튼과 분리하고, 무부하에서 멈춘 것을 확인한 뒤 사용한다.

## 4. 버튼과 메시지 규칙

아래 표는 구현 목표다. 시안의 버튼 활성 상태가 실제 펌웨어 검증 결과는 아니다. 서버의 상세 상태·시간·메시지 계약은 가이드004를 정본으로 삼는다.

| 항목 | 활성 조건 | 동작 / 거절 표시 |
|---|---|---|
| 제어권 받기 | 정상 현재 세션, 다른 소유자 없음 | 기존 소유자가 있으면 관찰 유지, 강제 빼앗기 없음 |
| 운전 허가 | 내가 조작, 선택축 정지·프로필·통신 확인 | 허가 처리중에는 이동 금지, 실패하면 정지·오류 |
| D0/D1 | 내가 조작, 해당축 허가, 최신1회 이동표, 다른 이동 없음 | 1회만 접수. '오래된 화면입니다 / 다시 상태를 확인하세요' |
| 모든 축 정지 | 정상 연결된 관찰/조작 세션 | 조작권 없이도 가능. 연결이 없으면 '전송 불가'와 물리 차단 안내 |
| 토크해제 | 내가 조작, 정지 확인됨 | 별도 확인 후 해제. 움직이는 중 해제 버튼 비활성 |
| 다시 점검 | 오류 원인·필수 수동 확인 조건 충족 | 상태 조회부터, 자동 운전허가 없음 |
| 기록 보기 | 항상 | 네트워크가 끊기면 마지막 기록 시각 명시 |

표시 우선순위는 정지 미확인/오류 → 정지 처리 → 통신 오래됨 → 이동중 → 허가됨 → 대기다. 색상만 쓰지 않고 문구와 아이콘/배지를 함께 표시한다. 터치 목표는 최소44px를 기준으로 잡는다. 키보드 포커스·상태 변경 알림·축 탭 선택 표시도 제공한다.

부팅 때 이미 유지토크가 걸려 있으면 **유지보수 제어권**으로 정지·무부하를 확인한 뒤 토크해제와 재점검을 수행한다. 이 권한으로 이동하거나 운전 허가를 할 수 없다. 오류 상태의 정지 미확인은 먼저 물리 차단·진단 재개 조건을 해결한다. 탭을 축2로 바꿔도 축1의 허가가 이전되지 않는다.

### 세 가지 흔한 상황

1. **두 휴대폰 접속:** 둘 다 상태를 보지만 한 곳만 제어권을 갖는다. 다른 관찰 화면의 정지 요청은 허용한다.
2. **이동 버튼을 두 번 누름:** 새 이동을 쌓거나 자동 재전송하지 않는다. 첫 요청 상태를 표시하고 중복은 거절한다.
3. **휴대폰 잠금/화면 전환/연결끊김:** ESP32가 제어권 만료를 감시한다. 복귀하면 상태 확인부터 시작하고 이전 이동을 복원하지 않는다.

### 화면의 수치

현재 위치는 엔코더 응답값으로 표시한다. 유효 값이 없으면0 대신 `—`, 오래된 값이면 '마지막 수신값'과 경과시간을 함께 표시한다. 100펄스는 모터1.8°·MStep16 조건에서11.25°이며 모터축 기준이다. D0/D1의 실제 회전 방향은 수령 시험에서 라벨링한다.

## 5. 부품 없이 할 일과 부품 도착 후 할 일

| 지금 준비 | 이번 산출물 / 검증 범위 |
|---|---|
| 상태·오류·중복 처리 결정 | 가이드004. 독립 문서 검토 후 지적 반영 |
| 화면 배치와 문구 확인 | HTML 비연결 시안, 모바일 렌더·가로 넘침 확인 |
| 정상/오류 시험 입력 설계 | 시나리오006. 아직 실제 테스트 코드를 실행한 결과는 아님 |
| 개발 환경 후보 선정 | ESP-IDF v5.5.6 + legacy TWAI + SoftAP + 내장 HTTP/WS. 설치·빌드 미실시 |

| 다음 구현 단계 | 완료 기준 |
|---|---|
| CAN codec / 상태 코어 | 실제CAN 없는 호스트 시험에서 정상·오류 프레임과 상태 전이 확인 |
| ESP32 adapter / 웹 자산 | 선택 SDK 버전으로 빌드, fake/real 경로 혼동 방지 |
| 실제 보드 읽기 시험 | 핀·종단·전원·실물FW 확인 뒤 버전/위치/상태 읽기 |
| 작은 이동·정지 시험 | 퓨즈·차단·고정 확정 후 가이드003의 순서로 진행 |

**남은 실제 확인:** K1 단자 회로·퓨즈 정격, 모터 명판과 드라이버 FW, ESP32 PCB·USB 방식, heartbeat 실제 동작·저장 여부, 정지거리/시간, 통신 오류·발열. 100펄스 이동으로1초heartbeat 정지를 검증할 수 없으므로 별도 시험 조건을 확정해야 한다.

CAN 응답에 요청번호가 없어 오래된 응답과 최신 응답을 항상 구별할 수는 없다. 조회 지연 상한과 수신 처리 시간을 실제 프로필로 확인하기 전에는 운전 허가를 막도록 설계했다. 문서상 시간 후보나 화면의 모의 상태를 실제 운전 검증으로 취급하지 않는다.
