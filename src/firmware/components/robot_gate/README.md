# Offline control gate — ST3-1

`ControlGate` is single-owner, noncopyable C++17 request validation. No CAN frame, network, GPIO, SDK, allocation or clock API. It is not wired into app_main. Immutable Config freezes boot/profile/active topology; default approvals deny control. Trusted adapter registers at most two sessions, trusted supervisor supplies monotonic consistent snapshots. Wire parser, Host/Origin, entropy/boot uniqueness and actual enable handshake are NOT implemented here.

Acquire lease (800ms), explicitly arm already-enabled proven stopped axis, obtain ticket (500ms), submit fixed100pulse/speed5/acc2 request. One reservation spans pending intent through trusted stopped completion. `take_intent` revalidates current time/snapshot; dispatch_before and binding must ALSO be enforced immediately before/after actual submission by future ST3-2. Copying returned intent outside gate is not prevented. No queue/retransmission, retained request watermarks prevent replay. Authenticated observer stop bypasses lease and replay watermarks but never authorization checks. Stop is terminal and coalesced; future explicit recheck requires new gate lifetime with fresh boot identity. No old permit restoration.

Identity exhaustion, clock reversal/overflow, inconsistent snapshot and profile changes fail closed with fault/stop. Same snapshot revision requires identical explicit fields; no padding comparisons. `Status.error` preserves first stop reason, escalated once if later fault arises, so repeated stop does not hide errors. Output clearing on failed take prevents stale struct reuse. Configuration/count/axes supported: [1], [2], [1,2]. Only active axis entries participate in profile/health checks.
