# 100 결과 — 관리자 승인 취소 / 시간 정렬 미완료

2026-11-01. 사용자의 `작업계속이어가'`를 직전100의 두PC 시간 정렬 승인으로 받아, OS 한정 최대600초 작업을 시작했다. 실물 CAN과 시뮬레이터는 범위에 포함하지 않았다.

## 관측과 실제 실행

로컬·기존 SSH 별칭 isaacpc의 읽기 조회는 각각 transport 종료0이었다. 두PC 모두 W32Time **Stopped / Manual**, Type=NTP, NtpClientEnabled=1, 기존 peer `time.windows.com,0x9`를 확인했다. 로컬 토큰은 비관리자, 원격 토큰은 관리자였다. status/verbose와configuration의 native 명령은 양쪽 모두 **0x80070426(서비스 미실행)** 으로 실패했다. 이는 서비스가 없거나 NTP 동기화에 성공했다는 뜻이 아니다. 각 native 출력은 바이트 원본으로 보존했다.

로컬에서 승인된 Start-Service/resync에만 한정한 관리자 승인창을1회 요청했다. Windows Start-Process는 **“사용자가 작업을 취소했습니다”** 라는 오류로 종료1을 반환했다. 이 메시지는 Windows의 반환 기록이며 사용자가 의도적으로 취소했는지까지 판단하지 않는다. 요청부터 반환까지124.953초였고 당시 원기한은37.015초 남았다. helper 실행 전 실패했으며 배타 action marker와action result도 생성되지 않았다. 따라서 로컬 서비스 시작/resync 각0, 원격 변경 각0이다. 추가 UAC나resync는 요청하지 않았다.

600초 기한은 처음 monotonic27877.796에서28477.796으로 한 번만 고정했다. 이후 만료를 확인하고 OS·SSH 명령을 더 발행하지 않았다. 후속 작업은 저장된 로컬 증거 분석·문서화·Git 보존뿐이다. UAC 취소가 최초 중단 원인이고 기한 만료는 재개 금지 경계다. 원기한을 새로 잡거나 시간 정렬 성공으로 바꾸지 않는다. 첫 inline Python 초안은 실행 전 문법 오류였으며, 수정과 승인 대기 모두 같은 원기한에 포함했다.

## 수용 상태와 한계

시간 정렬 **미완료**. 작업 후 서비스 상태와 새 상대 시계차이는 **미관측/UNKNOWN**이며 초기 Stopped 관측을 현재 상태로 승격하지 않는다. 099의 약+3.42초 상대오차는 당시 값으로 보존하고 새 측정값으로 재사용하지 않는다. 어느PC가 실제UTC에 맞는지와 서비스 중지가 유일 원인인지는 여전히UNKNOWN이다.
