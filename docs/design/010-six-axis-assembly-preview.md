# 010 — 6축 전체 조립 참조 모델 열기

2026-10-23 사용자 요청: “검토하면서 6축 로봇 모델링 전체 조립도도 만들어서 띄워놓으면 좋아”.

상태: **REFERENCE_ASSEMBLY_DISPLAY_READY**. L2 R1/R2 계획 PASS, L4 R1 MET8/UNMET0 PASS. Thor 변환은 기구 부품 실패·누락 면 경고로 표시 부적합. 아래 §4의 Faze4 URDF 전체 링크 조립 대안을 준비하고 실제 SolidCraft GUI에 열어 두었다. MP1 보조품은 동결 보존. 처분 정본은 `.dev/assembly-evidence/disposition.md`.

구현 중 확인: 루트 FCStd는 외부 링크를 따라가지 않아 직접 가져오기 실패. 저장된 BREP별 가져오기와 원본 링크 변환 합성으로 전환했다. 기존 Arduino Mega의 저장 형상에서 reader의 CollectionItems 1,000,000 한도가 발생했다. 이 부품은 사용자의 Waveshare 보드와 다르다. 모든 형상을 진단하되, 제어보드 같은 주변 전장품만 실패하면 정확한 누락 목록을 화면·README에 드러낸 **6축 기구 조립 참조**로 전달할 수 있다. 이 결과를 원본 전체 BOM/상세 CAD의 완전 재현으로 부르지 않는다. 주요 6개 모듈·관절·그리퍼 등 기구 형상이 실패하면 전체 기구 조립 확인은 미완료다. 실패한 형상을 임의 원점·가짜 형상으로 숨기지 않는다. L2 확인 검토에서 이 범위 구분을 확인한다.

진단 후 전환: 몸체·베어링 고정부·GearPlate 등 기구 형상도 실패했고 성공 반환된 BREP에도 face/loop 누락 경고가 관측됐다. Thor checkpoint는 진단용으로만 남기며 사용자용 완성 조립 파일로 전달하지 않는다. 대신 확보된 Faze4 URDF의 7개 링크·6개 관절·원본 STL을 명시된 xyz/rpy로 조립한다. 원본 STL 좌표는 m, SolidCraft 표시 단위는 mm이며 bbox를 교차 대조한다. 이 모델은 전체 링크 배치 시각화이며 제조 상세 CAD·독립 그리퍼 개폐 모델·관절 구동 시뮬레이터가 아니다. 실제 LICENSE(CERN-OHL-S v2)를 보존하고 README의 MIT 배지와 상충함을 명시한다. 최종 L4는 이 대안과 Thor 미완료 진술의 정확성을 검토한다.

## 범위

- 기존 MP1 보조품 검토 결과는 보존하고, 받은 자료 중 **Thor의 저장된 전체 조립 CAD**를 검토용으로 변환·표시한다. 사용자의 최종 본체 구조나 MKS CAN MT 장착 호환을 확정하는 결정이 아니다.
- Armold 전체 CAD는 미확보다. 화면·README·모델 이름에 Thor 참조임을 명시한다. 실제 조립순서/BOM 검증, 간섭/강도/기구학 및 6축 구동은 이번 결과로 승인하지 않는다.
- 원본: `docs/references/packages/01/mechanical_refs/Thor/upstream/freecad-src/Assembly.FCStd`. 최초 인벤토리로 도달 가능한 FCStd53개, 외부 링크 인스턴스70개, 누락0을 확인했다. 이 숫자는 실제 부품 수가 아니다. FeaturePython은 저장된 객체일 뿐 Python·매크로 재실행을 하지 않는다.
- 이미 설치된 SolidCraft의 `file.insert_step`/FCStd reader로 **저장된 형상과 배치**를 읽고 새 native 파일로 저장한다. 폴더명은0.18.2이나 실행본은 CLI/GUI에서0.18.4로 확인됐다. FreeCAD 원본이나 PrintForge 코드는 수정하지 않는다.

## 산출물과 확인

1. `models/six-axis-reference/`에 native 조립 파일, 가능하면 neutral STEP/3MF, 등각·정면·측면 미리보기, 출처·CC BY-SA4.0 라이선스·원본스냅샷/해시.
2. 내보낸 전체 형상에서 바운딩박스·유한좌표·링크/바디/연결체 개수(각각 구분)를 확인. 원본 6개 주요 서브어셈블리 Base/Art1/Art2/Art3/Art4/Art56와 그리퍼 형상이 실제 표시되는지 확인한다. 개수만으로 조립완전성 판정하지 않는다. 원본 썸네일/배치와 비교한다.
3. SolidCraft GUI에 참조 조립을 열고 로딩 완료와 모델 표시를 확인해 사용자에게 남긴다. 같은 모델의 PNG를 Codex에도 보여준다. 필요하면 기존 trimesh의 로컬 내장 HTML viewer로 회전·확대용 보조뷰를 생성하되 외부 CDN/전송 없이 사용한다.
4. 외부 링크 해석이 안 되거나 일부 형상이 누락되면 성공으로 표기하지 않는다. 원본 서브어셈블리 저장 배치를 사용할 수 있는지 조사하고, 그래도 불가하면 그 한계를 남긴다. Faze4 URDF를 쓸 경우 링크 시각화이며 상세 기계 조립 CAD가 아님을 명시한다.
5. 원본·보조품·펌웨어 불변을 확인하고 인계 기록을 갱신한다. 실제 출력/구매/장치 제어는 하지 않는다.
