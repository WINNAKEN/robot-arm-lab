# 084 — 변경 모터 사양 대조와 CAN 도착 전 준비

2026-10-30. 문서 대조만 수행. 구매·플래시·실물 CAN·보정·모터 운전은 실행하지 않았다.

## 현재 확인된 내용

| 구분 | 확인 내용 | 현재 시뮬레이션 반영 |
|---|---|---|
| 사용자 최신 보고 | J2/J3 시험에 사용할 몸체 40 mm NEMA17 두 개 준비됨 | 실측 질량·관성·토크 상수까지 확인된 것은 아님 |
| 사용자 최신 보고 | 일부 최종 축은 더 큰 모터로 변경 진행 중 | 정확한 축별 모델이 확정된 입력으로 반영되지는 않음 |
| 보유품 E01 | MKS SERVO42D CAN MT 두 세트 도착 | HW/FW·정격 라벨은 도착품 대조 전 |
| BOM L02 / 예산표 | J2/J3 NEMA23-56 + SERVO57D 또는 긴 NEMA17 + 앞단 감속 후보 | 문서 상태는 여전히 두 축 실측 후 결정·보류 |
| 통신 모듈 E02 | Waveshare ESP32-S3-RS485-CAN-U 선택, 사용자 배송 대기·다음 주 예상 | 실제 도착품과 펌웨어 통신은 미검증 |

관련 생산 대화 `01a1821e-d9ba-7052-a739-ebbd6ba2fcbe`와 현재 `docs/BOM.md`, `docs/BOM-budget.md`를 대조했다. 조회된 대화도 어깨 NEMA23를 대안으로 구분한다. Mech-Sparring 폴더에서 이번 로봇암의 추가 확정 사양 문서는 찾지 못했다. 이는 변경이 없다는 뜻이 아니라, 이번에 확인한 문서만으로 최종 축별 사양을 확정할 수 없다는 뜻이다. BOM·CAD 소유 파일은 변경하지 않았다.

현재 동역학 시험은 기존 CAD/URDF의 가정 질량·관성과 기존 토크 제한을 사용한다. 더 큰 모터를 쓴 최종 로봇을 검증한 결과로 취급하지 않는다. 특히 15항 역동역학 추정은 모터의 실제 PD 구동 토크 측정이 아니다. 부품 사양을 추정해서 토크 한도를 올리거나 정착 실패를 통과시키지 않는다.

## 다음 모델 개정에 필요한 축별 입력

J1~J6 각각 모터 정확한 품명, 몸체 길이, 드라이브 모델·CAN 옵션, 모터+드라이브 질량과 무게중심, 감속비·효율 가정, 관절 출력 토크/속도 제한을 한 행으로 묶어야 한다. 미확정 행은 PENDING으로 둔다. 그리퍼는 별도 구동계로 기록한다. 모델 개정 시 CAD → URDF 질량/관성 → 구동 한도 → Isaac 재검증을 함께 갱신하며, 기존 시험과 다른 모델 버전으로 보존한다.

## 통신 모듈 도착 전 준비

- [ ] 모터 A/B를 구분하고 실제 CAN 단자명·HW/FW·정격 라벨 사진을 수집한다. 외형이나 판매 사진으로 핀 배열을 확정하지 않는다.
- [ ] 실제 수령 보드가 CAN-U 외장 안테나형인지 대조한다. 현재 보유 ESP32-WROOM은 별도 보드이며 S3 핀 설정을 그대로 사용하지 않는다.
- [ ] E09 RVSP 4core 24AWG 선택/주문·보유 상태를 확인한다. CAN H/L에는 동일 꼬임 쌍을 쓰는 계획이며, 차폐를 기준 GND 도체로 대체하지 않는다. 사진만으로 120Ω 특성 임피던스가 확인된 것은 아니다. 전원은 별도 18AWG 두 선이다.
- [ ] 종단저항은 버스 양 끝의 실제 내장/외장 유무부터 확인한다. 각 노드마다 추가하는 방식으로 배선하지 않는다. 최종 배선 검토 전 무전원 상태를 유지한다.
- [ ] 기존 codec·정지 경로·휴대폰 권한/취소/시간 시험 자료를 도착 후 시험의 대조 자료로 준비한다. 이번 단위에서는 펌웨어나 승인 플래그를 변경하지 않는다.

구현 대조: `src/firmware/components/robot_twai/idf_twai_port.cpp`는 ESP32-S3 TX GPIO15 / RX GPIO16, 500 kbit/s, RX queue16을 사용한다. 이는 준비된 코드의 설정이며 실제 보드·드라이브 설정이 일치한다는 확인이 아니다. 보드 회로도/도착품과 드라이브의 실제 bitrate를 대조한 뒤 별도 시험 계획에서 확정해야 한다.

`src/firmware/main/app_main.cpp`는 ESP-IDF v5.5.6 / ESP32-S3 대상으로 제한되며 하드웨어 승인 상수는 false다. 기본 빌드는 CAN·네트워크를 시작하지 않는다. 준비 실행부 선택도 실물 운전 허가를 뜻하지 않는다. CAN 부품이 도착해도 자동으로 토크 허가·보정·운전을 시작하지 않는다.

## 문서 사용 순서와 남은 경계

현재 수량/선택은 `docs/BOM.md`, 돈은 `docs/BOM-budget.md`가 정본이다. `docs/design/003-wiring-and-can-command-guide.md`에는 예전 CF888 길이·구현 전 설명이 남아 있으므로 최신 배선 정본으로 그대로 따라 하지 않는다. 연결부 설계는 `docs/design/008-esp32-build-and-can-adapter.md`, 실물 운전 없는 점검은 `docs/specs/bench-no-can-checklist.md`를 참조한다. 해당 체크리스트의 과거 예정일은 실행 완료 근거가 아니다.

도착 후에는 부품 식별 → 핀/전원/종단 무전원 대조 → 별도 승인된 최소 통신 시험 순서의 계획을 새로 확정한다. 출고 설정상 전원 인가만으로 토크가 생길 수 있으므로 ‘CAN 미연결’과 ‘무토크’를 혼동하지 않는다. 현 단계는 통신 시험 준비이며 실물 통신 PASS 또는 운전 준비 완료 판정이 아니다.
